# BP 权限只读核查与开发者权限边界

核查日期：2026-11-05。当前运行链仍为 `116ea0c3c556951ba0a9244cbfbfe13f98972f3353c38ff38c35122d0f61c5a0`，不是尚未部署的新链。

## 用户最后确定的规则

- BP 提供出块、验证、最终性和节点服务，按既有协议领取奖励；治理上只对 dev 提案拥有否决权。
- dev 权限逐项开放，不加入通用超级用户执行器，不恢复旧 BP 多签管理通道。
- 不加入强制修改别人账号权限或资产的操作。用户持有人正常签名改权限、转账不受此限制。
- 系统账号保持封印，不增加系统账号改钥匙提案。`eosio.key` 尤其不能交给外部钥匙或管理账号；其中托管的用户资产不能当成系统资金。
- `usd`、`cny` 的最新选择是普通发行账号，初期自愿委托 `eosio.dev` 账号管理，不复制私钥：owner → `eosio.dev@owner`；active → `eosio.dev@active` 或自身 `eosio.code`。合法所有者以后可以签名交接。这不属于系统托管，也不是对既有用户账号的强制改权。
- 合约可正常升级。保障模型是公开代码、参数、影响及精确摘要，完整公示，BP 有效否决，执行内容不能替换。不能把它描述为资产合约永久不可修改的数学保证。

04:00 UTC 起的只读 RPC 观察覆盖全部 **25 个已注册 BP 账号**，全部 `privileged=false`。注册数不等于有效或健康节点数：当前 24 个有效 BP，保留原 Germany 永久封禁。

| 能力 | 当前结论 | 依据 |
|---|---|---|
| BP 单独或联合接管系统账号 | 未发现可用管理权限路径 | `eosio` owner 阈值 1 但无 keys/accounts/waits；active 仅自身 `eosio.code`，不委托 BP |
| 通过 `eosio.prods` 获得旧式 BP 多签权限 | 关闭 | owner/active/prod.major/prod.minor 均无可满足的授权；原生 `update_producers_authority` 在治理配置下直接返回，不随轮换重建 BP 权限 |
| 经 `eosio.wrap` 或 `eosio.msig` 绕过账号授权 | 关闭 | 二者非特权、权限封印；原生 `apply_context` 在治理封印后拒绝执行这两个账号的合约 |
| BP 修改系统权限/部署系统代码 | 不具备直接能力 | 原生受保护权限检查拒绝改权；系统代码变更须由指定开发者经完整审核及一次性摘要绑定能力执行 |
| BP 冻结别人资源 | 不具备该管理员授权 | `setacctcpu/setacctnet/setacctram/setalimits` 要求 `eosio` 授权；BP 身份及其联合签名不满足此权限 |
| BP 强制修改普通账号 owner/active | 无 BP 专属入口 | 原生权限管理依然核对目标账号有效授权；BP 无特权代理通道 |
| BP 强制转移、扣减用户代币或改公钥账本 | 无 BP 专属入口 | 已部署 token 转账要求发送者授权；KEY 出账验证用户证明。中继提交权限不能替代用户签名 |
| 任意授予 BP `privileged` | 封印后原生禁止 | `set_privileged` 仅允许 `eosio` 保持特权，不能给其他账号提升特权 |
| 否决 dev 提案 | 保留 | 当前原生 TEST 公示 1800 秒；对冻结有效选民按既有至少 2/3 门槛计票；提案 3 的 24/24 否决仍保留 |

上述结论指 **BP 身份本身没有管理他人的权限**。用户若主动把自己账号委托给某个 BP，后者依据该用户的授权行事，不能与 BP 原生管理权混淆。任何账号可按规则调用的开放动作（例如符合全部条件的保证金结算）也不是 BP 任意没收权。

## 不能扩大解释的边界

1. BP 能在自己的节点上拒收交易，或拒绝出块/最终性签名；联合恶意行为可能导致审查或停链。删除账号管理权限不能从共识层消除这些可能性，既有轮换、失职和保证金规则继续约束它们。本次未改变共识或惩罚规则。
2. 目前资产合约及系统合约仍能经 dev 提案升级。恶意升级可能加入冻结、改账或授权绕过代码；因此本报告**不宣称任何人永远不可能间接改变用户资产**。用户选择以公开审查和 BP 否决防范这类提案，而非本次冻结所有资产合约代码。
3. 原生审核只能验证精确摘要、时间、选民和否决结果，不能自行证明代码意图良善。BP 不投否决票不是明确赞成；低于门槛的提案期满后可由合法开发者执行。
4. 新权限、第三方发行账号创建策略和新链部署仍须分别通过远端验证；本次只读核查不等于新候选全部合格或已经上线。
