## 起因及限定

[二级成本取证](PX7_SECONDARY_COST_DIAGNOSTICS.md) 记录实际晚授权两笔批次：普通版 1 worker 编译 6 次、4 worker 13～20 次；ASan 条件下对应 5～6 / 10～15 次，并发生多次准备截止。普通关闭计量的第三轮也发生一次准备截止。它们支持研究缓存局部性，不证明所有截止都由调度迁移引起。

候选只在任务数不超过线程数时稳定分配逻辑 worker，使每笔任务有自己的线程，同时避免 joined 发现轮之间无必要地换缓存。超过线程数保留原共享队列。原单任务固定 worker 0 的语义不变；不绑 OS CPU、不迁移 VM、不共享模块/数据库指针，不复用旧结果/快照，不改原预算或默认开关。

## 限定实现与审查

仅改生产 `parallel_worker_pool.cpp`：batch 在发布前根据不可变的任务/线程数量选择稳定小批次或共享队列。最多 16 个逻辑 worker，固定大小的 claimed 数组与原队列游标都只在原 mutex 下读写；小批次任务 i 只能由 worker i 领取一次，大批次仍使用原 next 游标。任务执行仍在锁外，owner 仍等待所有 remaining 归零后返回，取消、失败清空、结果顺序和原数据边界均不变。

没有修改公开 job/outcome/API、controller、VM 缓存容量、共识或计费。单任务自然仍固定 worker 0；线程数上限仍是原 16，仅统一为类内常量。人工核查领取条件的索引边界、互斥、每任务一次、退出/唤醒和异常清理；访问清单只更新该文件哈希，没有新增状态访问或 host。24 项审计及清单精确匹配通过。新固定输入仍为 70 项，除调度文件和其清单外的 68 项逐字节同负对照，31 项原实现不变。
