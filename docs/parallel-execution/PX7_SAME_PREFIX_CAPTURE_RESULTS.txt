PureEOS：同一前缀的不可变状态捕获复用
日期：2026-10-20；feature/parallel-tx-execution；未发布，TPS未验。

解决什么
原实现发现缺失数据后，每轮都从正式库重新复制此前已捕获的内容。
本次只复用单次同步准备中、正式状态没有变化的查询与行；没有减少发现轮数，
也没有取消整批等待、权限/资源校验或有序提交，不称为已解决全部并行开销。

如何避免过期余额
controller::prepare_isolated_attempts 在栈上创建一个捕获 session。
worker 只拿不可变快照；全部返回后，owner 才能扩展下一版快照。
旧版表映射不变，新增查询使用写时复制；行数据是 const 共享所有权。
成功结果保留自己的旧快照和 ticket，未完成位置拿到新快照与新 ticket。
session 不跨函数返回：提交、新批次、当前前缀冲突重试均创建新的 session。
回滚/重建后的值与对象身份必须重新读，不能将共享行指针当作正式状态版本证明。
此作用域“没有正式库写入”的前提来自现有同步控制流，不是跨批 MVCC 缓存。

涉及文件
libraries/chain/include/eosio/chain/parallel_state_overlay.hpp：
  新增 owner-only frozen_primary_capture_session；表/行的 const 共享所有权，
  累计查询计数及仅用于验证的源读取/行复制计数；返回快照不包含 live view。
libraries/chain/parallel_state_overlay.cpp：
  稀疏捕获只读取未捕获查询；扩展表映射写时复制。未知查询仍请求数据，
  不从稀疏行推断缺失/邻接；负查询、五类二级索引语义保留。
  行、字节、表、账户、主键＋二级查询预算按全部内容累计，失败不发布半成品。
libraries/chain/controller.cpp：
  单次 prepare 构造/使用 session；不改变50ms生产/500ms验证准备保护、
  发现轮次、worker上限、原正式采用与失败回退。
unittests/parallel_state_view_tests.cpp：
  新增六项：不可变旧版本、负/未知查询、跨扩展累计预算、取消/线程亲和、
  主键二级联合边界、新 session 与撤销后重新读取。
