证据：`build/local-tests/parallel-secondary-cost-20261016-B753iM/`；程序归档预留：`/run/media/guagua/新加卷/pureeos-secondary-cost-artifacts-20261016-Dox5LA/`。

## 实际失败与研究问题

[混合诊断接续](PX7_MIXED_FAILURE_DIAGNOSTICS.md) 的二级补测首轮出现四条失败：family=0/1/3/4、4 worker、晚 inline 授权场景均准备截止，原账本/撤销/尾交易/复用检查通过。这个场景是两笔交易（复杂故意失败交易与简单尾交易），不是单任务固定 worker 优化覆盖的情况。

不能只凭线程数把根因指定为冷缓存或调度迁移。本批先测原实现的阶段成本，保留准确失败程序；不变更生产调度、状态捕获、模块限额、50ms/500ms、100 压力或原断言。

## 仅测试诊断改动

`unittests/parallel_secondary_wasm_tests.cpp`：

- 针对原两笔失败批次和单笔健康复用，复用 opt-in `parallel_test_measure` 的编译/执行次数与时间、整段墙钟。
- 仅本测试文件的辅助函数增加状态捕获、批次等待、采用、回退四类原计数器快照，全部在 joined 调用前后取值；需要环境变量 `PUREEOS_PARALLEL_TEST_METRICS=1` 才启用。
- 每条记录含 family、RAM/授权场景、worker 数、late/healthy 阶段，补充实际准备/worker 错误分类和采用/内部回退计数。
- 原交易和所有权限、RAM、账本、轨迹、回执、采用/回退断言不变。其他 69 项输入逐字节不变，31 项原实现不变；没有改共享诊断头文件或生产文件。

等待包括 worker 工作，编译/执行是跨 worker 累计值，且正式回退也在整段墙钟内；这些指标不得相加、推算 TPS 或当作共识计费。开启计量本身可能增加开销，只作为诊断条件，不替代未开启时的验收。

## 预定检查

单个 `-j1` 构建，核验真实运行库。对同一旧晚失败用例，预定三次独立 ASan/UBSan/LSan 成本诊断进程，普通断言失败继续收集预定样本，总状态保留失败；检测器错误/崩溃/看门狗终止立即停。无绑核、抑制或预算放宽；三轮未复现也不能认定旧失败修复。

## 后续候选边界（尚未实现）

源码复核显示 `parallel_worker_pool.cpp` 只对单任务固定逻辑 worker 0，多任务发现重试仍让任意空闲 worker 取共享队列；模块缓存线程独占。可先验证一个有界候选：**任务数不超过线程数时**，相同位置任务在各次 joined 批次由相同逻辑 worker 执行，每个任务仍有独立线程；超过线程数保持原共享队列。此方案不是 OS 绑核，不移动 VM，不复用旧结果/快照，不调整预算或开放默认开关。

必须先补实际多任务缓存/并发负对照，验证 2/3/4 任务、1/2/4 worker、各执行模式和新状态/代码/限额/取消/失败后复用；再根据负对照决定是否实施。小批次调度可能影响唤醒及负载分配，不能只看编译数下降就称整体更快。修改后需配对本批实际两笔场景、普通/完整/插桩、消费者及真实节点测试。此候选不承诺解决单线程 500ms 压力截止或所有 50ms 准备失败，G5/G6/G7 仍未关闭。

本批构建及测试已结束。两个新诊断批次只改测试和记录，未改生产实现、默认开关、共识/经济/治理、`main` 或回退标签。原失败与新结果分别保存，下一阶段从多任务缓存负对照继续，不把本取证批次算作优化已实现。
