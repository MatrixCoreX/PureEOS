## 为什么先做这一项

c3b 保留的 ASan 失败是实际 worker deadline 和采用计数不足，不能仅因无内存报告就验收。源码显示，每个普通根和同步子帧都会重新构造、编译模块；编译进入同一个私有编译互斥锁。既有诊断中编译开销明显，多个线程的累计编译时间还包含相互等待。它是有证据的优化目标，但尚未证明是偶发超时的唯一原因。

修改前，针对原完整递归/父返回值正式采用对照，普通和 ASan 各三轮通过，每轮 1 个实际用例、454 条断言；保留 `baseline-normal-{1,2,3}.log`、`baseline-asan-{1,2,3}.log` 和 `baseline.sha256`。这些只建立本批对照，不能抹去 c3b 的完整套件失败。

## 代码与安全边界

- `parallel_sync_call.hpp` / `parallel_wasm_worker.cpp`：每个同步执行器独占九个深度槽，根使用 0，最多八层同步子调用各占一槽。同一深度每次独占借用；活动槽不能被再次借用，父槽不能被子调用淘汰或重置。
- 活动和休眠模块合计最多九个，不在既有九个活动实例之外再加另一套缓存。每槽按**原始代码字节和全部七项 VM 限制**精确匹配；替换先销毁旧实例，完整构造后才发布新 key。失败不保留半初始化模块，归还不分配内存。
- 不缓存权限、代码支持位、只读标记或协议观测。每次仍按原顺序验证；冻结输入、完整指纹、首写前证明、正式授权/RAM/undo 路径保持不变。
- 复用的是已编译实例，不是合约运行结果；每次仍运行原 `execute_step` 的 memory/globals/start 重置，host、迭代器、返回值和同步 trace 均新建。缓存查询和编译也消耗原单个绝对尝试预算，不延长 500ms 私有或 50ms 生产上限。
- 只影响实验同步执行器；旧普通 action-tree 缓存和原链 VM 资源池不变，实验默认关闭，OC 仍关闭。

这里选择深度分槽而非跨深度 LRU：它直接保证嵌套生命周期和总实例上限，代价是同一代码出现在不同深度仍需不同实例、同一深度频繁切换代码会重新编译。这不是无限缓存或通用性能承诺。
