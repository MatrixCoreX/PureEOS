# 首版正式发布后的单节点 TPS 压测

2026-10-24。本文件是后续执行协议，未启动 TPS 测试，也未购买压测服务器。先完成首版联合发布，再执行本协议；不将旧样本重新标为当版结果。

测量前固定已公开的 tag、准确节点程序和四工具摘要、AIC CDT SDK 摘要、实际合约 WASM/ABI、创世和资源参数。当前候选尚未正式发布，不能预先填写最终发行身份。

压测阶段只运行一个实际 nodeos，承担出块及单成员 Savanna 最终确认。发送器独立进程，其 CPU 单独记录。需要独立重放/账本复核时，在测量结束、节点暂停和采样关闭以后进行，不能把第二个验证进程的负载混入单节点测量。

在同一临时云主机上使用同一个发布程序，比较串行与 4/8/12/16 worker。实际 vCPU、物理核/SMT 可见信息、共享或独占类型、steal、内存、磁盘及操作系统均记录。不把虚拟线程数称为独占物理核心数，不宣称测试找到了所有硬件上的绝对上限。服务器型号、实时价格和账户限额在正式发布后再核验选择。

负载分别执行：

1. 实际 eosio.token 转账，使用不重叠的收发账户和足额余额，检查整个语料的业务读写独立性。
2. 独立简单合约调用，每笔实际读写独立业务行，保留真实代码和权限检查。
3. 复杂合约调用，固定每笔 root/action 数、计算次数和结果校验，事务内依赖保持顺序。
4. 混合负载：50% 简单、50% 复杂；50% 关联、50% 独立。统计冲突、重新准备、采用与串行回退。
5. 系统资源动作单独做正确性和吞吐观察；特权路径可能按设计串行，不能用 token 转账代替所有 eosio.system 动作。

默认协议参数先测。每档速率先低速冒烟，再逐档加压；正式比较采用预先固定的模式顺序、预热期、稳态窗口、排空期和三轮样本。不同模式使用相同程序、资源预算、交易内容和初始状态。过载拒绝、超时、队列积压及未最终确认交易全部报告；不能只计算成功子集或挑最快一轮。

只把固定窗口内最终确认的唯一成功交易计为链 TPS。接收速度、action/s、整批完成率、执行耗时和重放速度另列。检查余额/供应守恒、复杂结果、原始收据、最终分支及状态摘要，记录发送器不足、外部进程噪声和缺失采样。

另设实验创世预算时，串并行仍用相同预算，结果单独标注。区块累计 CPU、最小交易 CPU、NET 和本地执行期限全部从实际参数读取；不能靠增加预算或改计费制造并行倍数，也不将诊断预算写回正式代码或发布包。重点区分串行提交、准备/复制、冲突、JIT 编译、签名、发送器、CPU 计费和硬件饱和各自造成的限制。

服务器有独立费用截止和精确 UUID 清理。测试结束后先下载、逐摘要验证完整报告及失败证据，再删除该台压测服务器。任务完成以实际报告为准，不在发布前填写 TPS 预估数值。

执行准备核对：现有 `tests/parallel_release_benchmark.py` 和global12脚本默认同时
运行出块节点及验证节点，不能直接把其结果写成单节点TPS。正式发布后先增加
明确的单节点测量路径：bootstrap块直接喂给唯一出块节点；窗口内最终确认
观察同一节点的实际LIB；采样只含该nodeos及独立发送器。测量结束、出块停止
并关闭CPU采样后，再另起验证进程从日志完整重放，并对照固定head的完整性摘要、
业务余额/行、收据和资源参数。不得把第二账本的负载算入测量，也不得删除独立
复核来换吞吐。原双节点结果继续按原拓扑保留。该路径尚未执行压测。
