## 本批实际改动

1. 二级读取适配器可以从原主键适配器建立，继承同一数据库与原 owner 的线程身份；外线程连构造也拒绝，不能将两个不同数据库的读取拼接成一份快照。主键适配器只增加定向 friend，未改变其虚函数接口或成员布局。
2. `secondary_query` 区分精确字典键和数据库排序，归一化仅去掉原语义不使用的参数。find-primary/first/last 清除无用键位但保留类型；find-secondary/lower/upper 清除无用主键；next/previous 保留完整 tuple。±0 的值查询仍保留不同精确输入位，不能因排序等价而无条件复用另一个查询的证明。
3. `frozen_primary_state::capture_queries_with_secondary` 将主键和五类索引放在同一表元数据快照内，合用表数、行数、查询数和值字节预算；二级行按 `(索引族, 主键)` 去重，值预算计入原二级键的 8/16/32 字节。共同 query 限额在相减前验证，避免无符号下溢。没有捕获的查询返回拥有值的缺失请求，不能从稀疏行推断邻居；已捕获的“不存在表”才可以证明有效查询均无结果。
4. `state_capture_request` 增加显式二级分支，保留无抛异常复制约束。controller 的请求处理显式区分 account / primary / secondary；新捕获入口仍在 owner 完整 join 后调用。controller 随后与准备阶段修复一并重建并通过下述核心回归，但没有二级 host 产生请求，不能记作二级索引正式采用验收。
5. 新状态实现并入共同 state-view 静态库，原 secondary 专用链接名变为 interface target，避免循环静态链接。native / WASM / secondary 插桩目标显式列入其实现，而不是仅插桩调用者。

还没有二级索引写入覆盖层、游标/日志、原 host 正式重放或 WASM host 准入。当前普通合约不能因为这些修改就被称为已支持二级索引并行提交。G6a 的原程序与源码已另行保存，不能拿它们的结果当作本批验证。
