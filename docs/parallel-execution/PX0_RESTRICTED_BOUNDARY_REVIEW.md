# 受限并行路径的访问边界复审

日期：2026-10-11。范围是当前代码哈希白名单下的解释器试验路径，不是所有合约已支持并行，也不是 262 个原 host 都已改造。新接入代码的验收结果另见阶段测试记录；本文记录源码推理及必须维持的边界。

PX7 补充：下文固定保留 PX0–PX6 历史边界。G1/G2 已改为精确查询依赖和按查询捕获；G3a 又扩展内存/断言入口及显式仅回退导入桩，设计、重新审查及测试见 [PX7](PX7_GENERAL_EXECUTION_PLAN.md)。因此下文“15 个 host、其他全部拒绝链接、要求显式内存最大值”不再是当前版本的完整边界。主键生命周期限制、原序提交和 owner 独占正式数据库仍不变。

G3b 补充：新增账户身份/存在性按需副本和有序通知日志。账户实际读取进入依赖，不包含无关 receipt/auth sequence；任何未知账户需要 owner 复制，不能猜不存在。采用前逐一检查通知接收者账户、代码和原生处理器；仅无代码、无对应原生 handler 的通知可按原 `require_recipient/exec_one` 重放，不省略回执。不支持的子调用整笔回退；`send_inline` 仅获得可链接且调用必回退的桩。当前分类为 25 支持／9 仅回退／228 拒绝链接，262 项原注册没有自动全部批准。

G4a 补充：已支持既存行 resize/payer，按当前私有元数据读取长度与内容、按原序保存全部中间更新；资源/权限仍由 owner 的原 host 判定，失败整笔撤销。通知增加相对写入位置，避免 RAM 更新失败时遗漏先前已调度的 trace。分类仍为 25／9／228；store/remove 仍不是已支持接口。验收见 [G4a](PX7_G4A_RESULTS.md)，下文同 payer/长度仅为首版历史限制。

G4b 补充：store/remove 已接入私有生命周期及原 host 正式重放，分类变为 27／7／228。临时 ID 不进入正式 DB；结构变化使整表后续旧尝试失效，稀疏查询不猜相邻行。旧行句柄不能在重建后复活，退役表旧结束句柄明确回退。验收见 [G4b](PX7_G4B_RESULTS.md)；多 action/带代码调用树/二级索引仍未开放，owner 独占正式数据库的原则不变。

## 1. 两条路径不能混为一谈

正式 controller、权限/资源管理器、原生 action、插件回调仍只在原 owner 上执行。工作线程不调用原 `webassembly::interface`，不拥有 controller、Chainbase、pending block、资源管理器或插件引用。

工作线程的可达状态只有：有界复制的表、输入 action、独占 WASM 模块/实例、私有迭代器和写日志、停止标记。它使用另一个模板实例 `registered_host_functions<isolated_host>`，不复用原 `interface` 注册表。

因此，未适配的原数据库入口不是“默认安全”；它根本不在工作线程注册表中。代码包含任意未支持导入时，整个模块在链接阶段失败，尚未执行 start/apply，原交易在正确顺序位置走完整串行路径。即使导入未实际调用也保守回退。

`unittests/parallel_audited_intrinsics.hpp` 固定列出当前 262 个生产注册名字。Python 审计将它与真实注册和分类清单做集合相等检查；WASM 测试逐一验证其中 247 个非支持名字不能链接。新增生产接口不能靠宽泛前缀匹配获得并行许可。

## 2. 15 个支持入口逐项契约

| 入口 | 私有读取/写入 | 正式采用的必要条件 |
|---|---|---|
| `current_receiver` | 复制的 receiver | 与当前 action/account 一致；只支持顶层首次接收者 |
| `action_data_size` | 复制的数据长度 | 指纹绑定完整输入字节 |
| `read_action_data` | 复制的数据，写独占线性内存 | 保持原返回长度语义；检查完整目标 span；无内存/零页保守回退 |
| `has_auth` | action 声明授权列表 | 授权列表纳入指纹；不是密码学验签结果 |
| `require_auth` | 同上，检查 actor | 正式路径仍执行原权限树和签名检查；失败试算不能代替正式拒绝 |
| `require_auth2` | 同上，检查 actor/permission | 同上；原实现目前不维护额外“已使用授权”状态 |
| `set_action_return_value` | 私有字节输出 | 指纹绑定当前协议返回上限；正式 action 摘要在原路径生成 |
| `db_find_i64` | 有界基础表/覆盖层，含不存在记录 | 整表读取依赖；未知表不解释为“不存在” |
| `db_lowerbound_i64` | 主键有序查询，含空范围 | 整表依赖覆盖范围边界/幻读 |
| `db_upperbound_i64` | 同上，严格上界 | 同上，包含最大主键边界 |
| `db_end_i64` | 私有表迭代器 | 不泄漏正式对象指针；表元数据/生命周期必须匹配 |
| `db_get_i64` | 私有迭代器定位，读取自己的写入 | 保持长度查询/截断复制语义，完整缓冲区边界检查 |
| `db_next_i64` | 私有迭代器，更新主键输出 | 整表依赖，保持 end/无效句柄及未对齐输出语义 |
| `db_previous_i64` | 同上，含从 end 倒退 | 同上；句柄运算避免负数边界溢出 |
| `db_update_i64` | 仅已有行、相同 payer、相同长度；保存每次有序写入 | 必须是 receiver 自己的表；原 host 重放，任何 payer/长度变化整笔回退 |

调用深度、内存页数、代码哈希与上述输入一起绑定执行指纹。模块内存必须声明最大值且不超过当前协议与本地上限，防止本地较小预算使 `memory.grow` 返回不同的成功分支。更低的调用深度只允许抛弃试算，不能提交一个被截短的执行结果。

## 3. 其余访问类别明确隔离

| 原入口类别 | 当前处理，不隐含准入 |
|---|---|
| 主键创建/删除、payer/大小改变、所有二级索引 | 模块不支持或私有更新守卫失败；整笔串行，保留 ID、RAM、表 count、undo |
| 账户存在性、权限树、链接、代码/ABI、权限使用时间 | worker 无这些 host；正式授权与元数据读取在原顺序执行 |
| 通知、inline、sync-call、deferred、onerror | 不链接/入口屏障；不拆分一笔交易分别提交 |
| 配置、资源、协议特性、治理、生产者/finalizer 修改 | 系统/原生/privileged 在准备阶段拒绝；相关导入不链接 |
| 交易上下文、块时间、其他未复制上下文查询 | 不链接，不从共享 controller 临时读取 |
| crypto、compiler builtins、console、内存 helper | 尚不注册；不能把“通常纯计算”当作已证明安全 |
| injected 浮点 host | 不注册这些导入；原解释器浮点 opcode 使用依赖库，另审查 SoftFloat TLS |
| RPC/trace/state-history/Deep Mind | worker 无信号入口；正式事务走原信号路径；当前 Deep Mind 模式保守串行 |

原主键 host、管理器和 Chainbase 不需要为了这一受限路径批量重写。`chainbase_transaction_state_view` 只在 owner 上读正式库并返回拥有所有权的值；新执行器没有“未经视图而私下访问正式库”的后门。将来扩展能力时必须重新评审，不能沿用这个结论。

## 4. 正式写入及生命周期

1. 批次冻结发生在 onblock 后和区块交易顺序位置；复制有表数/行数/字节上限。
2. worker 全部退出本批执行后，owner 才取得结果；队列/模块不会持有数据库引用。
3. ticket 绑定不可复用的批次身份、交易位置和 ID；结果绑定基础副本与执行指纹。
4. 前序写表使后序读表失效；一次回退取消本批余下试算，即使前序写回旧值也不消除冲突。
5. 原交易上下文完成授权、去重、TAPOS/过期和资源初始化后，才到原 WASM 调用位置尝试采用。
6. 采用前再次比较完整受限表、对象 ID、payer、长度和值，含不存在/范围结果。不能只比较最终余额。
7. 先完成会分配内存的校验/返回值复制，再通过原 host 重放有序写入。重放后异常只能走原 undo，不能捕获后再串行执行一次。
8. 原 action receipt 的全局、接收、授权、代码和 ABI 序号，以及事务计费/输出仍在 owner 上产生。
9. 批次对象局部持有；abort/抛异常后不留向新块回填的 future。外部中断通过拥有生命周期的原子 generation 使正在执行和排队任务失效。
10. controller 析构先 join 工作池，再销毁运行时和数据库。批次数固定为一个，线程数最多 16，每线程缓存一个独占模块。

区块验证沿用区块收据的显式 CPU。PX5 另加默认关闭的生产端入口：采用成功结果时，在首次正式写入前一次性补记其私有执行耗时；保留交易/账户主观 CPU 截止与块墙钟截止，并沿用原队列回调。未经这个计费入口的非显式 CPU 交易不能采用私有结果。详见 [生产端设计](PX5_PRODUCER_DESIGN.md) 与 [验收记录](PX5_ADOPTION.md)。省略数据库 undo 的快速回放、轻验证、OC、profiling 和 Deep Mind 当前不进入本路径。

## 5. 非 Chainbase 依赖

- host 注册初始化使用 `call_once`；编译/解析/链接在小范围互斥中串行化，避免原 resolver 的非 const 容器访问。正式 WASM 执行不持该锁。
- WASM 线性内存、栈、globals、执行上下文、allocator 和模块都由所属线程独占；模块替换/销毁也在所属线程。
- EOS VM 信号目标、内存范围、异常暂存均为 TLS；全局处理器使用 C++ 静态初始化保护。本地超时改为每 1024 opcode 协作式检查，不依靠修改其他线程代码页。
- SoftFloat 原构建的舍入/异常状态已改为 TLS 编译定义，未改依赖子模块源码；实际实现的插桩检查单独记录。
- 不调用原 sync-call allocator pool，不共享原运行时缓存，不接入 OC 编译回调。
- 解释器仍有内存异常信号路径，必须做真实越界恢复和多模块复用测试。TSan 与 fortified longjmp 的兼容检查不等于可以关闭生产硬化。

## 6. 结论边界

以上是“15 个严格受限 host + 其他全部串行”的可行边界，不是通用 EOS 合约并行支持。原扫描快照中的 `pending` 指原 host 的全面并行改造审查，不能被简单改成全部安全。阶段完成还必须满足真实采用、非法块/undo/切叉、真实进程和旧程序互验等运行证据；未完成项必须在主进度记录中保留。
