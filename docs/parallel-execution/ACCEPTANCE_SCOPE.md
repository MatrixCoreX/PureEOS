# 首版验收范围与原计划对照

本页区分“支持并行采用”“明确串行回退”“本地测试未能证明”。它不是对全部 EOS host 开放并行的批准。详细用例、计数、产物哈希和报告路径以各阶段记录为准。

本页固定记录 PX0–PX6 首版（`0068f79`）。后续扩展与新代码证据见 [PX7 滚动计划](PX7_GENERAL_EXECUTION_PLAN.md) 和 [G1/G2 验收](PX7_G1_G2_RESULTS.md)，不要将下述历史计数当作后续版本的重测。

G3b 覆盖真实 EOS/PureEOS token 的既存余额、无代码通知；G4a 放开既存行长度及 RAM payer，G4b 新增主键创建/删除、表生命周期、正式 ID 分配与恢复差分，见 [G4a](PX7_G4A_RESULTS.md)、[最新 G4b 验收](PX7_G4B_RESULTS.md)。本文历史表中的限制不得替代最新记录；多 action、带代码子调用及二级索引仍未并行。

G5a 已验收多 action 的**私有执行器基础**，见 [记录](PX7_G5A_RESULTS.md)，但正式生产/验证入口还保持单 action。其多 action 单元与串行 oracle 不计作正式采用、区块互验或完整调用树已完成。

## 不能从“首版完成”推导的结论

- 一般 EOS 转账、REX/PowerUp、索引/通知/inline/sync-call 的安全串行兼容，不等于这些合约获得多核加速。
- 未加入通用 MVCC、流水化冲突重试、并行 OC、复杂跨合约并行、自适应热点降级。这些属于原计划列出的后续扩展；本版遇冲突直接关闭本批余下试算并串行，成本有界但不保证性能退化小于 5%。
- 没有生产链饱和 TPS、云服务器倍数、跨机网络长尾、物理断电、硬盘损坏或数月运行结论。12.8 分钟本地持续测试只能证明该有限场景。
- ASan/UBSan/LSan 和 TSan 的插桩范围是私有执行与相关原生模块，不是整个 nodeos 所有第三方依赖；TSan 明确排除两项未插桩 controller 对照。
- 性能记录保留阶段计时、实际采用/回退、进程 CPU/RSS 和主机信息；没有将这些数值冒充精确 allocator、每个缓存对象或确认票网络队列的完整剖析。

任何扩大白名单能力或默认启用，都必须重新做边界审查及对应负载验收。首版保持原主链规则和默认关闭，是性能测量后的交付选择，不是偷偷扩大准入来提高数字。
