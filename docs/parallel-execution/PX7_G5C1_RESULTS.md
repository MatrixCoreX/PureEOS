# PX7 G5c1：带代码通知的私有执行基础

日期：2026-10-12。分支 `feature/parallel-tx-execution`，起点 `7ddd658`。本阶段已按下述私有通知基础范围验收，尚未接入正式采用；不能据此宣称带代码通知已能并行上链。

## 实现与边界

新增线程独占的 `isolated_notification_executor`，接收有所有权的冻结状态、根动作和调用期间保持不变的代码目录。工作线程不读取 controller/实时数据库；缺失接收者返回拥有名称值的捕获请求。目录中空字节码明确表示已存在的无代码接收者，`serial_only` 标记不得私有执行的程序；这些调用方提供的信息本身不是正式代码/权限证明。

同笔交易共享一个私有状态覆盖层。每个根动作建立自己的游标和通知去重集合；根及其通知共用它们，按原来的可追加队列顺序执行。通知再发给根、自身或已排队接收者不会重复执行。新根重置组状态，但读取前一组留下的私有写入。游标切换接收者不解除表所属代码的写入限制；每次 WASM 执行仍重置内存/start 和返回值。

先保留全部顶层 ordinal，再分配通知 ordinal；输出按实际执行顺序记录根归属、action/creator ordinal、接收者、代码哈希、每步写入区间及通知调度位置。例如两组四接收者的顺序为 `1,3,4,5,2,6,7,8`。所有步骤完成才 seal 一次，任何缺失数据、trap、越权、未支持接口、取消或超限均不返回成功前缀。

边界为 16 个根、256 个程序、256 个实际步骤、每组最多新增 64 个接收者，总代码和根输入分别最多 256 KiB，整笔绝对预算最多 500 ms；原覆盖层读写预算不按接收者刷新。每个线程仅缓存一个独占模块。inline/sync-call 未支持；现有工作池/controller/adopter 仍使用 G5b 的顶层模式，带代码通知继续整笔串行，实验默认关闭。

## 下一步的明确风险

G5b 正式采用只重放写入和通知，略过纯读取；这对共享游标的带代码通知不足。若前缀读取已经分配句柄而正式缓存没有相同记录，后续转串行会改变游标编号。G5c2 必须先加入影响游标缓存的有序读取/变更轨迹，再接入 owner 代码捕获、全树预检和按执行步计费；不可直接删除根动作限制。实施文件及差分要求已补入 [滚动计划](PX7_GENERAL_EXECUTION_PLAN.md)。
