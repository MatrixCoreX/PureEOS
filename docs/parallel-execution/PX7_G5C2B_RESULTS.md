# PX7 G5c2b：通知全树预检与正式接入

日期：2026-10-12。分支 `feature/parallel-tx-execution`，起点 `f265a03`。**本批已按受限通知采用范围验收，不表示全面并行已完成。** 证据目录为 `build/local-tests/parallel-notification-preflight-20261012-1IgvVV/`。

## 本批改造

- `parallel_wasm_worker`：在另一份私有覆盖层上验证整树队列、ordinal/creator、代码/输入指纹、游标查询返回值、写入对象及代际、通知位置、读取依赖覆盖和总预算。读依赖只能是原证明的子集；当前账本校验仍单独执行，不能把冻结副本上的自洽当成当前有效。
- `parallel_worker_pool`：通知任务独占所有根输入与代码字节。结果与旧顶层模式互斥；状态缺失及接收者缺失分别返回拥有所有权的请求，深层失败没有成功前缀。切换模式销毁旧 executor，保持每线程一个模块缓存；计时只累加有代码步骤，无代码末尾不能覆盖最后一次 WASM 的结束时间。
- `parallel_canonical_adoption`：owner 捕获账户、元数据及代码，原生/特权/缺失能力不进入私有模式。第一步重验完整树及当前依赖，再通过原 host 按原顺序重放查询、变更和通知，不额外添加 find。当前步骤的防御失败只能在开始重放前回退；步骤内原 host 的失败仍走完整交易 undo，不局部重跑。
- `controller`、`parallel_ordered_batch`：接入通知结果类型、接收者补捕获和每个子代码的本地名单检查，仍保持批次所有工作线程结束后才读取当前数据库。新发现程序可增加原每根 8 轮发现额度，但总计最多 64 轮，整批 500 ms、生产 50 ms 绝对预算不刷新。
- `apply_context`、`transaction_context`：普通与无代码通知均消费明确步骤；CPU 防重复绑定执行步及实际 ordinal，不假定 ordinal 连续。原权限、资源、RAM、回执和 undo 路径保留。实验仍默认关闭，inline、sync-call 及一般二级索引不在本批开放范围。
