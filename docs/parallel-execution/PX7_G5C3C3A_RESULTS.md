### c3b 接入前的进一步核查（研究记录，尚未修改）

`apply_context.cpp` 目前在一次同步采用后立即清空 `parallel_sync_result/input`；`transaction_context::charge_isolated_cpu` 又明确要求同步根 ordinal 为 1、整笔只有一个 action。仅扩大 worker 根数量会让后续根丢失能力或重复/漏计 CPU，必须同步改造消费游标和计费防重。整笔冻结/当前状态证明只应在首写前完成；不能在第二根用已被第一根合法修改的链状态重新比对最初副本，也不能在首写后失败时从头重跑父交易。

正式多根重放需要每根独立的 call ordinal、entered/return/子树 CPU 缓冲，同时共享整个结果的绝对写入区间；每根按原顺序收费并经过原 RAM/授权/异常检查。全目录及全部根已核验不等于任何根获准跳过原检查。新结果当前没有 controller/工作池消费接口，这些要求留给后续独立接入与故障矩阵。

进一步确定 c3b 的接入方向（尚未实施）：新增拥有多根输入的同步 job 和互斥 worker outcome，保留旧单根私有 API 的回归入口；controller 的同步升级统一准备交易级结果，即使整笔只有一个普通根也使用同一正式消费路径，避免生产代码维护两套不同的同步计费规则。`ordered_attempt_batch` 只增加新结果类型的完整指纹/状态检查，仍不提供授权。原调用树只在实际普通根触及同步 host 时发出升级信号，通知/inline 内的调用仍不因此开放。

`transaction_context` 的正式同步指针相应绑定交易级输入/结果，使用原有逐根消费索引；首根做完整冻结与当前状态证明，各根在自己的原 WASM 执行点建立短生命周期 replay。新根从其绝对 `writes_begin` 开始，但局部调用序号仍归零；只有最后一根完成才记整笔采用成功。原 undo/reset 必须清空全部能力；后根前置不匹配仅能退回当前及剩余根，不能重跑已成功前缀；当前根开始重放后的异常仍直接整笔撤销。

c3b 验收须增加整笔独占 CPU 总和与逐根单次计费、不同根 sender/游标、后根权限/RAM/VM 失败撤销、前根已写后尾部回退、缺失捕获重试、同表独立行与跨根冲突、取消与五模式切换；在普通/插桩后再做新节点生产及恢复。上述设计不表示代码已放开，也不把当前私有九组对照算作正式采用验证。
