## 本次具体修改

1. `parallel_console_host_tests.cpp` 的配置原先把 canonical 固定为解释器，私有
   引擎也使用解释器默认值；传入 `--eos-vm-jit` 并不会覆盖这个 fixture。
   现在通过已有统一选择函数同时配置两侧，并增加实际配置字段回归检查。
   这是测试覆盖问题，不声称修复了生产节点的引擎选择逻辑。
2. console/exit/environment 的每个场景先执行一个固定冷批次。冷批次仍检查
   每笔执行轨迹、返回、资源相关字段、状态哈希和独立验证的一致性，允许按
   现有生产规则在准备超时时安全回退。然后仍执行原有数量的两个强制采用
   批次，生产和验证都必须实际采用全部交易、没有串行回退。非最优首次执行
   不应误报为结果错误；热态也没有取消或降低真实采用断言。
3. 私有 sync 叶子并行用例显式覆盖解释器/JIT、1/2/4 线程。每组一个冷批次加
   三个固定暖批次，运行有界真实 WASM；所有批次检查返回与 journal，串行必须
   没有叶子重叠，多线程的三次测量中必须观察到实际叶子区间重叠。没有用根或
   编译区间冒充执行并行，没有新增测试 host 或重试到通过。
4. 用于同步启动测试线程的 barrier 在异常/未成功启动线程时减少参与者，防止
   一个 worker 失败后其他 worker 永久等待。执行器、模块和 runtime 仍各线程
   自有，不共享可变 VM 或正式数据库。

原准备/执行/内存/字节上限、计费、共识、14 天/1461 天/86400 秒常量均未修改。
这些修改解决测试模型/覆盖缺陷；是否仍存在生产问题须由实际复测确认。
