## 代码依据与预定边界

`controller::prepare_isolated_attempts` 在同步/混合模式升级时已经捕获根账号。真正同步目标在 worker 中先读取账号，再检查 flags，最后查找合约程序；未知的真实目标可能先请求账号、再请求代码，导致两轮完整 join/快照/重执行。普通 `is_account` 也会请求账号，但没有执行目标代码的必要，不能一概预取。

先测当前实际轮数和编译数，不预设节省量。若负对照支持实施，范围为：

- 新内部头文件 `parallel_sync_discovery.hpp` 与 `parallel_wasm_worker.cpp`：仅在实际同步目标的未知账号、且 flags 支持时，产生自有账号请求和同名程序提示。保留账号在 flags 之前的判断、缺失/无代码返回值、权限、只读、调用深度和所有容量/时间上限；普通账号观察、根账号缺失不带程序提示。异常类型只由 worker 与 pool 实现包含，不修改既有公共 job/result 结构。
- `parallel_worker_pool.cpp`：专用捕获只返回有所有权的两个请求，不返回成功前缀、旧快照或 VM/数据库指针；原异常基类捕获接口仍有效。
- `controller.cpp`：join 后由 owner 校验请求同名及模式；不存在的账号不消耗代码目录槽。沿用原代码白名单、协议/代码指纹、目录/字节预算，重新建立整个快照和尝试，不移用前轮成功结果。
- 普通/同步/混合、1/2/4 worker、单/多个根和交易；缺失、空代码、原生/未准入目标、flags 次序、失败撤销、重复目标、取消及容量边界，均需分别验证。不能只让两个新测试通过便关闭 G5/G6/G7。
