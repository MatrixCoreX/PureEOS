# CPU 计费修复与容量拆分记录

本轮只处理 CPU 费用及其对并行装块的影响。治理、奖励、CDT 与节点淘汰规则不在本轮修改范围；真实 24 小时奖励测试不重启、不缩短时间。

## 已确认的问题与修改

1. 原 owner 费用从墙钟差计算，调度等待可能进入费用。新增 `thread_cpu_billing.hpp`，使用当前线程的 `CLOCK_THREAD_CPUTIME_ID`；暂停期间不计 CPU，复位清除已放弃的尝试，跨线程、计数倒退及溢出拒绝。
2. 私有 VM 成功执行使用线程 CPU。嵌套 sync 调用按包含子调用的 CPU 差扣除，再累计各层自己的 CPU，防止子调用重复收费。墙钟开始/结束和真实截止保护保留。
3. 签名恢复在另一线程进行。签名恢复改用该线程 CPU，controller 按原配置比例传入 transaction_context；该费用在上下文重试后仍保留一份，不依赖人为前移墙钟起点。原签名 CPU 默认比例仍为 50%。
4. 生产插件的主观计费原来使用 trace.elapsed；新增本地 trace.cpu_usage，把成功/失败的 CPU 费用传给主观计费。elapsed 继续用于诊断。新字段不进入区块收据或 trace 的线协议序列化。
5. CPU 总和及转入 32 位收据前检查范围，显式收据的非法负数/超范围值拒绝。
6. 两项旧 CPU 测试曾通过传入未来 12ms 墙钟，期望额外收费 12ms。改为独立 CPU 时钟的上下界检查，并在暂停计费后证明未来墙钟参数不增加费用；原私有费用、序号、原截止与中断断言保留。

- 区分账户资源账单与全网统一的并行容量；不能把单节点核数写成各节点不同的区块有效性规则，不能直接把单笔账单除以核心数。完整依赖/热点保护及最低支持配置验证尚未实现。
- CPU 正确性及容量修改通过后，才运行冻结旧基线与新构建的同机、同语料、同额度对照。无新性能数据，不预报收益。

## 2026-10-25 容量计量组件进展

新增 VM 内部检查点指令，保留 256 个分发槽，原始合约不能编码该内部指令。
两个引擎使用同一解析规则，在基本块入口预扣原始非结构指令数；函数入口和
循环入口、回边另外扣正工作量，空函数和无限空循环也不能绕过预算。块内
发生陷阱时保留该块预扣量；它不是“只计算已经完成的指令”。目前每条指令
统一为 1，是尚未校准的实验工作单位，不能称为完整 gas 定价。

解释器和 JIT 共用每次执行的预算绑定，JIT 沿用异常桥接并保持栈对齐。
共享代码不保存可变计数器地址，嵌套绑定退出后恢复；原有墙钟中断仍然工作。
通用 visitor 若没有实现计量，会拒绝内部检查点，避免静默漏扣。

## 2026-10-25 01:30 补充回归与异常封口

本地又发现并修复了两个真实绕过入口：原生回调捕获工作量超限异常后直接
返回，或抛出 VM 正常退出/自定义提前退出标记时，原来的 VM 返回路径可能
没有再次检查失败状态。现在普通完成、正常提前退出与其他异常返回都会
检查该次预算；已经是工作量资源异常的对象直接重抛，保留动态异常类型。
原生与 VM 共用同一个资源异常类别，避免嵌套桥接改变原始异常。

增加 start 函数初始化计量：预算必须在 initialize 前绑定；初始化超限后
重置复用、无限 start 循环和原未计量路径均做对照。最新 16 组原生桥接及
23 组 VM 运行用例，在普通/ASan+UBSan/SoftFloat 各三轮通过，共 351 次。
该数字只包括这些组件；消毒器不覆盖生成的 JIT 机器码及缓存的 SoftFloat
库。失败原始记录、修复前源码和当前源码快照均保留。
证据：CPU-VM-completion-fence-20261025-attempt-1/report.json。

新增 observed_host_functions 可选适配器，委托原注册函数与类型转换器。
记录真实调用次数、模块/函数名、参数类型和原始整数/浮点位；相同参数的
重复调用也逐次记录，不能用查询去重数量代替成本。绑定属于线程局部栈，
共享合约代码不保存费用状态。超过 64 个参数明确报告不完整，不截断后
假装完整；参数类型/数量/注册表增长检查在原生副作用前完成。
这是成本采集接线组件，尚未用于生产注册表，也没有正式费率或完整访问证明。

云端冻结的 e8b5fdee 源码已通过 JIT/解释器各三轮原生回归，累计 4,581 次
用例执行；正在完成四实际账本进程联链。它冻结在本节异常封口及 M4 有限槽
修订之前，不替代这些更新的全节点验收。测试无 TPS 项目。
