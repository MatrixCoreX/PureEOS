# PX7 c3c/m0–m1：混合调用树私有执行与冻结证明（实施中）

日期：2026-10-14。沿用 `feature/parallel-tx-execution`，不覆盖 c3b 与同步深度缓存的未提交改动。证据目录 `build/local-tests/parallel-mixed-private-20261014-NdyjhK/`。

## 本批范围

先实现独立混合结果和私有执行器：普通步骤保留通知组游标/去重集合和 CF/普通 inline 两队列，同步调用在发送位置立即执行，子帧独占 VM 与游标。每个 action 步骤重新编号同步调用，整笔共享覆盖层、总调用/事件/字节限额和截止；inline 深度与同步深度分别计算。代码目录、所有 VM 限制、sync-supported 位、两类协议参数、CF 数据必须进入输入指纹。

普通步骤的游标、通知、inline 与同步调用写入同一有序事件流；同步子帧仍不得通知或 inline，CF 步骤不得调用同步 host。深度槽复用已有已测试算法，不增加跨线程共享模块。独占 CPU 时长只计每层自身执行，不重复计入子调用。

本批建立私有执行、原串行 oracle 及单一覆盖层的完整冻结重放证明，不接 controller/工作池/正式采用器；新结果不能转换成旧调用树结果供其采用。后续 c3c/m2 接入正式授权/重放、CPU 计费及真实节点。此处 m0/m1/m2 是混合树子阶段，不与早期 G5c3c0 资源池阶段混淆。不能把私有成功冒充上链采用或混合树全部完成。

### 后续正式接入约束

- 旧树的 `missing_sync_capture()` 仅为普通根给出同步模式提示；通知或 inline 内首次调用仍回退。需新增明确混合模式提示，普通根仍可保留旧同步路径；CF 和同步子帧越权发送继续拒绝，不得把模式提示当能力授权。
- 旧同步普通根调用通知/inline 时也要升级为混合模式；两种升级均复用原绝对准备截止、总发现轮数和自持目录，不能重领预算。
- 工作池新增互斥混合任务/结果，模式切换销毁旧 executor；计费汇总每步自身加所有子调用的独占 CPU，无代码接收者不覆盖前面的时间戳。
- 正式同步重放可复用原 `host_context::execute_sync_call`，但必须按当前 action 步建立独立能力、绑定父 host/局部 ordinal，普通事件同时交错执行原 inline 授权和通知调度。首步做整树冻结及当前账本校验；已采用前缀之后只允许剩余步骤串行或原整笔 undo，不能重复父写入。
- `transaction_context` 需独立的混合结果/输入及步骤计费防重复检查；不能简单放松旧同步“顶层连续序号”约束，也不能向旧 tree 计费器传入含子调用时间而绕开相等性检查。新增生产/验证、失败撤销和真实节点证据后才验收 m2。
- 最近同步返回必须继续由原 `execute_sync_call` 清空/更新；同组无代码/无 call 接收者不能清空。补“已采用父步骤 → 后续通知在事件前回退 → 原 VM 首先读取父同步返回”的对照，证明晚回退不破坏组级状态；新根/inline/同步子上下文仍独立。
