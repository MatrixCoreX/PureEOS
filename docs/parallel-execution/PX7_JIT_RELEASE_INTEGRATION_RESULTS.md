# 首版：独占 JIT 接入与同引擎 TPS 验收

更新：2026-10-19。分支 `feature/parallel-tx-execution`，工作区尚未形成发布提交。

## 本轮范围

落实已冻结的首版范围：最多 16 个 worker，独占模块/线性内存/栈/host 帧，
有序正式提交，不支持的操作安全串行。没有新计费协议、更多线程、数据库并行写入、
共享编译产物，也没有修改经济与治理规则。

## 已写入代码

- `parallel_execution_runtime.hpp`：不可变的本地解释器/JIT 策略；JIT 使用一份有界计时服务，
  每个活跃帧有独立的取消标志。运行时生命周期覆盖全部 worker 和缓存。
- `parallel_wasm_worker.cpp`：同一套私有 host、写集、调用树和指纹接入两种 VM；
  JIT 使用其自有元数据，start/apply/sync 均有超时和 memory.grow 本地回退；
  异常/嵌套返回时恢复调用方浮点控制状态。引擎选择不进入收据或共识指纹。
- `parallel_worker_pool.cpp`：每个线程保留自己的模块缓存，按显式策略创建 VM；
  不共享可变执行上下文，不使用全局/环境变量切换正式引擎。
- `controller` 与 `chain_plugin`：增加 `experimental-parallel-engine`，
  `interpreter` 对应 `wasm-runtime=eos-vm`，`jit` 对应 `eos-vm-jit`；
  不匹配时明确拒绝配置。保留代码 hash 审核、完整验证、无 trusted-producer/OC 等限制。
- `parallel_prefix_refresh_cases.hpp`：原七组真实生产/验证冲突与屏障用例增加同引擎 JIT 对照，
  包括 0/1/2/4/8/12/16 worker、改变写目标、异常撤销、授权、原预算与正式回调中断。
- `parallel_full_cdt_tests.cpp`：六组完整原始 CDT 合约生产/验证用例增加双引擎矩阵，
  不裁剪 WASM、导入或函数以通过测试。
- `parallel_release_fixture.hpp`：单独的新创世 profile 2 导出器，使用串行 JIT，
  64 个真实持久化行、唯一已签名交易、可固定计算量和热点比例。
  不修改默认区块 CPU/NET；此夹具没有系统合约账户资源配额，不能代替经济模型测试。

以上为实现状态，不代表全部验收通过。

## TPS 验收方式

`tests/parallel_release_benchmark.py` 只使用本版同一 nodeos，串行 JIT 对并行 JIT，
每轮共用相同创世/状态/签名交易/代码与区块限额。全新私有目录、回环网络，
真实生产节点和独立验证节点；固定预热、发送速率、测量窗口与排空时间，轮换测试顺序。
此场景是单最终确认人的新创世，两进程共享本机；不是 21 人委员会的网络容量测试，
也不能替代多最终确认人仲裁/故障测试或跨机器性能验收。

- TPS 仅统计窗口内首次观察到最终确认的成功用户交易 ID，不统计 action 数、RPC 接收速度或孤块。
- 对照报告全部轮次、中位数、最小/最大值、相对串行倍数和百分比；任一轮缺失/无效则不给出有效倍数。
- 首版“明显提高”暂按至少三轮中位数提升 20%，且最慢并行轮次仍快于最快串行轮次判断。
  这是预先确定的验收目标，不是已有结果；脚本完成/计量有效与该性能目标是否达成分别记录。
- 发送端跟不上、RPC 错误、采样错误或未排空均如实保留，不删除不利样本。
- 复核实际私有结果采用、独立节点完整状态哈希和全部 64 行累计值。
- 记录阶段指标、最终确认延迟、进程峰值 RSS/CPU、主机内存/频率/温度与编译干扰。
- 另外记录实际创世额度和各块收据 CPU/NET 总量，帮助定位配额瓶颈；收据总量不含
  隐式交易与 pending 开销，不能冒充完整资源账，也不直接由它推导硬件容量。
- 默认关闭阶段插桩测吞吐；`--metrics` 在两种模式同时开启，作为另一组诊断对照，不能混合比较。
- 分别运行低冲突、热点与计算负载；低发送速率通过不等于测到容量上限。
- 本机结果不外推为云服务器 TPS，也不把不同 VM 或更高额度混算为并行收益。

## 压力下新增的生产定时器修复

原 `producer_plugin` 在独立 timer 线程检查 correlation 后，向 owner 队列投递回调；
已投递的回调可以在重新调度/切块之后执行，且原 `uint32_t` 被两个线程非原子访问。
本次串行模式已出现这一风险对应的出块状态断言，不归因于 JIT 或私有 worker。
提前封闭当前轮次的满块是已有策略，**不把所有未来时间戳当作共识错误**。

- 新 `production_timer_guard.hpp` 使用原子代际，timer 完成与 owner 执行两个边界分别核对。
- 三类定时器（失败重试、生产、延迟切换）均接入 owner 复核；取消、abort 和 shutdown
  使旧代际失效。没有改变出块间隔、轮岗、CPU/NET 或最终确认规则。
- 新增独立 6 项测试覆盖排队后换代、只取消不重设、重复旧回调、跨线程读取、
  当前异常传播和捕获生命周期；真实生产集成及同负载压力检查随新节点构建执行。
- 计量/恢复纯脚本专项现为 **20/20**；后续 C++ 与整合实测结果见下文。

首个 `producer-timer-fix-OSpJz3/` 配置因独立测试目录未发现 `Threads::Threads`

### 已有证据支持的优化顺序

1. **先减少私有执行本身的额外成本。** 整数 4 worker 三轮阶段中位数：batch 等待
   3.484 秒，capture 0.0045 秒、adopt 0.0503 秒；私有执行累计 12.636 秒是跨线程
   包含式计时，不可与这些阶段相加当作 CPU。该负载的主要时间不是 capture/adopt。
   私有 JIT 在循环回跳和函数入口生成额外取消检查，当前走 C++ helper；普通 JIT
   没有这条检查调用。可研究内联快速路径，但必须保留取消、超时和异常恢复语义，
   不能删除检查来制造数字，也尚未证明它独占了全部差距。
2. **处理确定不支持的模块。** 为必要接口设计“链接可通过、真正调用时安全回退”的
   精确 ABI stub，或对确定的缺失导入做有界负缓存，避免每笔重复编译。
   不缓存 OOM/暂时取消/缺失状态等瞬时失败；实际调用仍走原始校验，不放宽权限。
3. **匹配复杂交易的批次与预算。** 生产私有准备整批最多 50ms，重放最多 500ms；
   batch 32 的复杂工作可能在准备完成前耗尽预算。当前日志不足以逐项分解全部未采用
   原因，需要补齐已存在但未输出的 preparation/worker deadline 计数，并独立比较
   较小批次。不能通过随意增大超时或绕过安全回退解决。
4. **将区块容量与执行并行度分开。** 整数串行样例平均计费 16,092.82µs/笔，
   原区块额度仍为 200,000µs；27 个非空业务块的交易数最小/中位/最大为 5/11/22。
   16 worker 不保证每批有 16 个任务可跑，更不等于 16 核算力。扩大测试链额度或
   新计费须另列实验，不能冒充相同规则下的并行收益。
5. **冲突判断仍可优化，但不是本轮唯一或首要证据热点。** 可测读写集合去重、紧凑
   存储、依赖检查重复工作和不相交集合快速路径；仍须保留权限、RAM、inline、
   主/次级索引和有序正式提交验证。零冲突不等于检查零成本，但这些样例无需冲突
   重执行仍未稳定提速，不能只改冲突判断就承诺倍数。

主机不是独占环境，且 `thermal-counters.jsonl` 记录到封装热限速累计时间实际增长，
不是仅凭温度高就认定降频。该旁路观测从整数第二轮中途开始，到首轮最大线程矩阵
结束；含测试间隙和其他程序，不覆盖之后最高线程实时补测，不把各逻辑 CPU 的
重复封装计数求和，也不将其全部归因于本测试。不能据此精确外推服务器 TPS。

重放工具新增显式诊断开关 `--allow-checked-serial-from-failed-adoption`：默认仍要求
整份实时报告通过；开关仅允许读取“未采用私有结果”这一特定失败报告中的**有效串行
检查点**，拒绝无效串行样本、状态不一致、其他错误或未结束报告。原报告不改写，

## 私有 JIT 中断检查快路径（2026-10-18，功能通过、性能未达标）

### 实现与安全边界

- `parallel_jit_backend.hpp` 为 context 增加当前 frame 的 atomic 标志指针。
  只有执行线程绑定/解绑该指针；计时器仅写 frame 的原有 atomic，注销计时器后
  才允许 frame 离开作用域。嵌套实例和不同 worker 不共享标志。
- x86-64 代码生成显式选择此 ABI：读取指针、空值检查、读取一字节中断标志。
  未中断直接跳过整个 helper 调用；未绑定或已中断进入原 C++ 异常桥。每个
  函数入口、每次循环回跳的检查都保留，没有改成抽样检查或删除监控。
- 使用真实对象计算成员位移，要求 lock-free 一字节 atomic，并在每次绑定时
  核对位移和基类地址；不对非标准布局类型使用 `offsetof`，不从空/伪造指针
  推算成员。x86 普通字节读取满足此 acquire 读取；这不是跨架构通用汇编。
- 普通 JIT 未选择 hook，代码生成保持原路径；只提供 C++ hook 的自定义
  backtrace 测试 context 继续走原 helper。保留栈对齐、异常长跳转、MXCSR
  恢复和 memory.grow 保护。代码容量上界同步增加，密集循环/函数继续断言检查。
- 维护约束：该快路径只适用于健康状态完全由这个标志表达的检查。以后若给
  `check_execution_budget()` 添加独立的新拒绝条件，必须同步修改快路径，不能
  假设汇编分支会自动执行新的 C++ 逻辑。

独立首次运行：**14/14 项、770/770 断言通过**。新增计数型 context 证明 10,000

绑定三次。现有无限循环期限/stop token/generation、三种循环回跳、直接/间接/
递归/start 调用、嵌套 frame、1～16 worker、内存增长、代码容量、浮点恢复均通过。

### 修改内容和边界

- `producer_plugin.cpp`：验签线程仍只 post 到 owner/read_write executor。
  已验签实时输入可进入最多 64 笔、4 MiB **估算占用**的 FIFO 暂存区；同优先级
  立即 post 排空，不引入等待定时器，不按 API/P2P 类型重排，不持有跨 post 的
  数据库会话、私有结果或 pending-block 状态。
- 排空时按当前出块状态、截止时间和已有容量感知建议进入现有私有并行执行器。
  单笔、不适合并行、暂停/非生产、准备中断、未消费尾部仍走原交易处理函数。
  满缓冲先排空；估算超限只是旁路优化，不新增拒绝规则。逐笔游标在回调前推进，
  避免异常后重放已消费输入；重入时使用原路径，不嵌套私有批次。
- 新 `incoming_transaction_batch.hpp`：owner-only 暂存/交换和共享一次性回调。
  回调先消费再调用用户函数；重试别名、重入和回调自身抛错都不能再次消费它。
  不声称进程被杀死或用户回调抛错时仍能保证外部 ACK 送达。
- `unapplied_transaction_queue.hpp`：容量检查移到插入/转移回调/计数之前，修复满额
  抛错后仍留下交易和错误计数；`clear` 同时归零笔数和字节；字节算术提前扩为
  `uint64_t`。保留原严格“小于上限”、同 metadata 重复 no-op、不同 metadata
  同 ID 回 duplicate、forked/aborted 优先级和容量规则。
- incoming MB 配置乘法提前扩为 `uint64_t`，修复大于 2 GiB 的 int 提升溢出；
  默认值不变。新增关闭时的本地 intake 统计及严格解析测试，不用调度次数冒充
  唯一并行采纳率或最终确认 TPS。
- 不修改正式区块额度、逐笔 CPU/NET 计费、奖励、经济治理、50ms 准备上限和
  16 worker 上限；未支持的合约操作仍回到原串行执行。
