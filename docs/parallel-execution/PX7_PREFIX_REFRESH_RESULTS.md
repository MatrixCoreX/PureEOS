## 实现

- `parallel_ordered_batch.hpp/.cpp`：新增 `inspect_next`，只判断候选可用、依赖冲突或不可用。它不消耗交易位置、不记录写集、不统计正式冲突；实际 `run_next` 才记一次冲突。旧提交入口仍在无法使用私有结果时停用整个尾部。
- 新增 `refresh_next`：只允许 owner 在已有提交前缀、所有 worker 已 join、当前正式 callback 尚未开始的边界调用。带重入保护的 capture 回调返回当前状态与输入指纹；保留交易 ID，发布新的不可变 preparation/ticket。旧 ticket 不能提交，旧结果不能换标签使用。
- 新 preparation 记录当前已提交前缀。当前位置重新执行的结果不再被自身快照已包含的前序写入误伤；其他旧尾部仍检查完整累计 dirty 集。没有清空主键、结构或二级索引依赖。
- 原 descriptor 集的去重快照 payload 仍限制为 4 MiB；总刷新次数另以现有 64 轮常量作兜底。**这不是每次刷新增加 64 轮，也不是全进程内存仅 4 MiB**：接入执行器时必须扣同一个发现预算并及时释放被替换的 outcome/ticket。外部 shared_ptr 自有生命周期，协调器不能替调用方释放。
- capture 抛异常会关闭批次；返回值验证、预算和分配失败不发布新 descriptor。停止后不能重开，不能刷新未来位置或使用仍保留的旧快照。
- 新检查不是授权或最终采用证明。即使返回 reusable，正式 adopter 仍须检查当前代码、权限、上下文、读取、资源和 journal；写集记账分配也可能触发回退。

## 新增测试目标

`unittests/parallel_ordered_batch_tests.cpp` 加入非消耗检查、七种结果类型指纹、错序/外来/过期 ticket、checkpoint 重入与异常、只刷新当前位置、旧结果改标签、刷新失败原子性、4 MiB 聚合上限、64 次兜底、跨线程误用和取消。现有五类二级索引范围、重复键、空结果、锚点与 ABA 场景同时检查新分类入口。

链式反例：A 写 X，刷新 B 后读取新 X 并写 Y，旧 C 读 Y 必须判冲突；再次刷新 C 后，独立 D 的旧结果仍可用。另检查刷新后的二级/结构读取不清除旧尾部冲突，简化结果的二级保护不能绕过。

这些测试的手工 owner 写入只用于协调器路由验证，**不是原合约执行、授权、RAM 或 canonical adoption 已通过的证据**。

## 接入执行器前必须完成

1. 将 `prepare_isolated_attempts` 的局部 deadline、剩余发现轮数和拥有的输入提取成批次存续状态。目前 `validation_attempts::cancel` 保存外层 cancel，不能代替函数局部截断到 500ms 的 `private_cancel`；后续重试必须保存和使用原绝对截止。
2. 保留每个位置的 roots、实际查询、账户观察、模式与代码目录，或基于最新状态有界重建；状态变化后允许发现新分支和新合约。不能重用旧查询结果、旧 environment 或代码目录而只更新指纹。
3. 复用同一线程池和同一 batch identity，当前 slot 每次真实执行使用最新 ticket；重试耗时只记录真实尝试，采用计费只使用最终成功执行的 CPU，不累加失败发现的 CPU。
4. 在生产与验块的 `run_next` 之前识别冲突并尝试重执行。未采用、未知/原生/特权路径、adoption slot 未消费、交易异常、外部中断、fork/abort 仍停止尾部；公开 push 的既有屏障不能删除。
5. 在同一新二进制下做串行差分：链式/全热点/独立混合、分支变化、真实资产、权限/资源失败撤销、切块与恢复。之后才讨论跨批次流水线、JIT 或容量提升。

### 编译期间的 N4 补充研究（未实现）

本地 `libraries/eos-vm/include/eosio/vm/watchdog.hpp` 的普通 `watchdog::guard` 每次构造都会新建 `std::thread`，析构时 join。若给每个私有执行/同步帧直接套这个对象，会把大量短交易变成频繁创建定时线程；不是可扩展的 4～16 worker 方案。下一步 JIT 原型须使用有界、可同步注销的计时/取消服务，或证明适合私有实例的等价机制；不能复用 controller 的非线程安全计时器。

`backend.hpp::timed_run` 的回调捕获执行线程 timeout 计数和帧内原子标记，再改变该模块代码映射权限；守卫销毁必须确保回调已完成，嵌套帧超时不能被内层退出清除。`x86_64.hpp::grow_memory` 直接调用 context，仍绕过当前私有 interpreter 的增长与 opcode 检查。以上两处必须先建立同等保护与取消复用/嵌套超时测试，不能只更换 backend 模板参数。这是代码研究，不是 JIT 已支持或 TPS 提升证据。
