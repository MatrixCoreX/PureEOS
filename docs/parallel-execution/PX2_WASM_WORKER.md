# 私有迭代器与独立 WASM 执行器

日期：2026-10-11；开发分支：`feature/parallel-tx-execution`。

> 本文为独立 WASM 初始阶段记录。后续已修订超时机制，并补充工作池、顺序校验和检查结果；当前进度以 [顺序批次记录](PX2_ORDERED_BATCH.md) 为准，下面的“尚在进行”不覆盖后续结果。

## 当前结论

已实现测试专用的主键 iterator 适配器和独立 EOS VM interpreter 执行器。后者执行真实 WASM、读取有界冻结副本、产生私有更新和返回值；没有 controller、Chainbase、资源管理器或原 host 的引用。

**仍未接入普通交易、区块验证或生产者，也没有正式状态采用路径。** 多线程私有执行通过不能替代 PX2 要求的“无需再串行运行 WASM、按原顺序采用成功结果”。权限验证、资源结算、收据、依赖冲突、epoch、区块中止及真实进程互验仍待后续闭环；本阶段不宣称 TPS 提升。

## 迭代器语义

`primary_overlay_cursor` 为每个 action 分配自己的整数句柄：行从 0 开始、表末尾从 -2 开始，-1 为无效结果。缓存只持有拥有所有权的元数据，不保存正式数据库对象指针。

支持精确定位、上下界、表尾、前后遍历、长度查询和部分读取；`previous` 使用严格前驱，不做可能溢出的主键减一。下一行/上一行不存在时，不改变输出主键。`db_next_i64` 收到小于 -1 的句柄时按原实现返回 -1。新的末尾句柄解码使用更宽整数，避免 `INT_MIN` 取负溢出。

更新仍仅允许当前 receiver 拥有的表、已有行、长度和 payer 不变。异常会使整个私有尝试不可封存。新增、删除、二级索引、同步调用和迭代器跨 action 使用均未开放；因此本版不能冒充已经处理删除后复活或 sync-call 广播失效。

## WASM 隔离边界

新实现为 `parallel_wasm_worker.hpp/.cpp`，仅由实验测试目标链接。采用单独的 host 类型及注册表，不继承原 `webassembly::interface` 或 `host_context`；未注册的 import 在链接阶段失败，不能落入原接口访问正式状态。

首批 15 个具体接口及读取来源如下。此表描述测试 host，不是链上白名单或生产入口批准。

| 接口 | 数据来源与限制 |
|---|---|
| `current_receiver`、`action_data_size`、`read_action_data` | 本次 action 的固定输入；私有线性内存中的有界复制 |
| `has_auth`、`require_auth`、`require_auth2` | 只检查该 action 声明的授权，符合原 apply_context 语义；不取代主线程验签及权限树验证 |
| `db_find_i64`、`db_lowerbound_i64`、`db_upperbound_i64`、`db_end_i64` | 私有 cursor；未知、未捕获的表触发整笔回退，不能伪装为不存在 |
| `db_next_i64`、`db_previous_i64` | 私有 cursor；输出主键用 memcpy，允许未对齐的 WASM 地址 |
| `db_get_i64` | 私有 cursor；长度/部分复制规则保持原约定 |
| `db_update_i64` | 私有更新日志；只有不改变行大小和付款人的已有行更新 |
| `set_action_return_value` | 私有返回值；同时受协议输入值和本地预算限制，正式输出尚未发布 |

没有提供 console、通知、inline、sync-call、deferred、密码学、权限修改、资源修改或原生系统行为。任何 import 缺失、执行异常、预算耗尽、超时或取消都必须让调用方丢弃整笔尝试并走原串行路径，而不是根据本地限制拒绝共识区块。

本地默认限制：代码 64 KiB、action 数据 64 KiB、授权项 64、返回值 4 KiB、16 个内存页、调用深度 64、单次试算 500 ms，且时间上限不允许高于 1 秒。状态副本与更新日志沿用上一阶段的独立限制。这些不是链上新参数。

较小的本地内存限制有特殊风险：`memory.grow` 可能返回 -1，使合约成功走入与正式执行不同的分支。因此仅接受声明了显式内存最大页数、且最大值不超过本地限制的模块。未来采用者还必须将该限制收紧到当前协议允许值，并在采用时校验相关上下文未变；不能省略此条件。

## VM 并发与生命周期审查

未修改 EOS VM 子模块，仍为 `3b3cde5951537700c6993d50c88885526431609e`。本轮将其 41 个 VM 头文件和构建文件纳入访问指纹；当前总扫描文件为 781 项。词法扫描仍不是线程安全证明。

关键发现：`backend::share` 共享 module，但 `backend::timed_run` 的超时回调会调用 `module.allocator.disable_code()`，改变代码页权限。因此不能直接复用原串行模块缓存为多个并发 worker 服务。

本实现每个工作线程独占 module、执行上下文和线性内存，不调用 `backend::share`。注册通过 `call_once` 完成；首次编译/链接序列化，避开上游 resolver 使用非 const 注册表查找的并发审查缺口。实际 WASM 执行不持有该编译锁。尚未实现有界多模块缓存或 OC/JIT 并行能力。

超时和 stop_token 取消通过独立、可等待结束的 watchdog 回调中断解释器。析构先等待回调线程退出，随后 VM 恢复代码权限；start 函数也在该 watchdog 内执行。每次执行重新初始化线性内存和 globals。取消仍需由未来批次身份检查把关，执行器的 stop_token 不能替代 controller 的 epoch。

VM 信号目标、超时标志和异常槽为线程局部变量；SoftFloat 的 C 库 TLS 修复见上一阶段记录。解释器路径不使用全局 JIT 代码分配器；后者虽有互斥锁和页对齐，也不能据此声称并行 JIT 已验收。

## 已取得的测试证据

- 状态/iterator：42 个用例、36,683 个断言通过，其中本轮新增 9 个 iterator 用例、120 个断言。
- 原 host 对照：使用真实 controller 和原 `apply_context` 的数据库方法，500 次固定种子操作，4,596 个断言通过；包括迭代器返回值、前后遍历、部分读取、更新后读取、原异常类别以及 undo 后完整性摘要恢复。
- 原生 Savanna 串行语料：TLS 修复后重建，19 块、569 个断言再次通过。上项合计为 2 个用例、5,165 个断言。
- SoftFloat：重建后 6 个用例、89 个断言通过，含新线程默认状态验证，旧库固定指纹仍一致。
- WASM 第一轮：9 个用例、95 个断言通过。覆盖真实私有写入、1/2/4 worker 执行调用重叠、超时及复用、取消、未知 import、越界/不支持更新后整次失败、线性内存/global/start 重置和线程归属。
- WASM 增补后：11 个用例、128 个断言通过。直接让原 controller 执行相同 WASM，对照固定 action/授权接口及真实行更新；原链行由串行初始化 WASM 创建，未伪造 RAM 记录。跨模块故障用例要求健康模块持续运行到另一个模块超时之后，再继续执行一次。
- Python 审计工具：23 个用例通过；新增 VM 内存/超时依赖变化探测。
- 状态、SoftFloat、串行参考、WASM、审计单测和审计快照共 6 项 CTest，逐项独立进程重复 3 次全部通过。

这些 WASM 测试只证明私有执行及所覆盖的原接口语义，不是正式采用。原生业务回归和 sanitizers 尚在进行，不能先记为通过。调用时间区间重叠也不是峰值 TPS 或 CPU 加速倍率证据。

证据目录：`build/local-tests/parallel-overlay-20261011-q42k0b/`。保留构建错误、修复后构建和每批实际报告，不把首次失败日志覆盖成成功。旧 nodeos 二进制、旧账本归档、主分支和系统合约没有替换。
