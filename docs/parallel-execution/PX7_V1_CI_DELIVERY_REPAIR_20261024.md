## 现在的入口

节点 `.github/workflows/build.yaml` 使用标准 `ubuntu-24.04` 构建机：

- Ubuntu 26.04 容器执行三轮候选工具检查，报告单独记录跳过数量。
- Ubuntu 26.04 / 26.10 两个真实用户空间分别配置独立 JIT Release 构建；编译
  nodeos、cleos、keosd、helios-util，以及状态视图、二级索引、入口合批和计时器组件。
- 使用各工具真正支持的参数检查源码版本；四项 CTest 必须完整注册、指向指定 ELF、
  实际执行成功，且运行前后八份程序摘要不变，才能关闭该组件报告。
- 仅上传检查记录，没有云平台密钥、自动购买主机、TPS 压测、部署或稳定版发布步骤。

CDT 使用相同标准构建机，在 Ubuntu 26.04 / 26.10 用户空间执行 SDK 源码检查。
该入口只检出当前仓库，执行完整 hardening Python 检查及真实 SDK 序列化/分配器的
普通和 ASan/UBSan 三轮；它不从旧节点包取依赖，也不下载一个旧 CDT 冒充当前构建。
此入口没有声称重编 LLVM、运行 WASM 全语料或生成完整 SDK。

外部 Actions 固定到已经通过 GitHub API 核实的官方提交，两个仓库均只有
`contents: read` 权限。容器共用构建机内核，不能由此认证全新 Ubuntu 内核。
构建机说明见 [GitHub 官方规格](https://docs.github.com/en/actions/reference/runners/github-hosted-runners)。
