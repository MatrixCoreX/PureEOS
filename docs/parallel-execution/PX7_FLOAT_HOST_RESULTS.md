## 实现边界

- `parallel_pure_float.hpp`：34 个显式操作，包括四则运算、取负、浮点/整数转换、比较。复用原 SoftFloat，保持原 `roundingMode=0` 转整数、NaN 返回值、饱和和负零规则，不用宿主浮点运算替代。
- 原八个 C helper 源码保持不变。`libraries/chain/CMakeLists.txt` 在独立静态库中用目标局部宏重命名为 `pureeos_private_*`，不覆盖原 `___*` 符号；sanitizer 另编译同源码的插桩副本，检查的是实际私有定义，不只检查包装函数。
- 三个有符号浮点转 128 位整数 helper 的指数 127 区间，以及 `floattidf(INT128_MIN)`，此前已在独立诊断中发现原 C 未定义行为。私有路径在调用它们前放弃整笔尝试，回到原执行；不产生新的共识拒绝，不采纳写入前缀。无符号 helper 不套用有符号边界。
- `parallel_wasm_worker.cpp`：34 个正确类型的 host，检查前后截止。保持原 `float128_t` 输出对齐 8 字节、整数输出对齐 16 字节及 legacy pointer 语义；浮点参数/返回值按原始位复制，不进行额外数值转换。普通、CF、sync、混合和 module start 均按原接口可用性测试。
- SoftFloat 使用 TLS 不等于 owner 与 worker 的数值环境一致。私有计算、准备和正式采用都要求原默认舍入、tininess、扩展精度；非默认环境不被重置，而是回到原串行。公开当前状态校验在检查点及完成依赖核验后再次检查环境。sticky exception flags 不是这些接口的计算输入或公开输出。
- `parallel_canonical_adoption.cpp`：准备及五类正式采用入口加数值环境保护，不改变账本、授权、CPU/RAM 结算、区块格式或治理/经济规则。
- 私有普通 host 44 → 78，拒绝集合 154 → 120；原 262 个注册接口不变。测试显式枚举集合并核对总数，不能靠遗漏拒绝项扩大覆盖。
