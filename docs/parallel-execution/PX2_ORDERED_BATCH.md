# 有界工作池、顺序校验与正式采用接入

日期：2026-10-11；本文件记录前一阶段之后的增量，不能将前后版本的测试混用。

## 已验证的隔离层

新增 `ordered_attempt_batch`：批次有独立、不可复用的进程内身份，ticket 同时绑定交易位置和原交易 ID。成功结果另有执行指纹，覆盖实际 WASM 字节的哈希、receiver/account/action、声明的授权、输入数据、返回值限制、内存和调用深度限制。

顺序协调器只允许 owner 消费下一个结果；旧批次、重复、乱序、错误交易、错误代码/输入指纹或不同基础副本不能被采用。整表读依赖与前序写表有交集时，转串行并取消本批余下试算。即使先写 B 再恢复 A，表仍视为已修改。原提交回调抛异常时关闭批次，绝不再调用一次串行回调来覆盖部分提交。

新增 `isolated_worker_pool`：1–16 个持久线程，每批最多 64 个任务，每线程最多缓存一个模块。工作输入、基础副本和输出均有所有权，worker 不持有 controller/Chainbase 指针。主线程等全部任务退出后才返回正式执行。单笔异常、编译失败、超时或取消只产生回退结果，不变成共识拒绝。

超时策略修订：解释器每 1024 个操作检查一次本地 deadline/取消，操作本身仍交给原 EOS VM visitor；start 与 apply 都受检查。每次执行仍重置 globals、线性内存、调用深度和页数。不再为每笔试算创建一个计时线程，也不使用异步取消修改模块页权限。正常内存异常的 VM 信号处理未删除；未修改 EOS VM 子模块。

### 不能记为通过的检查

最初把插桩后的 worker 与未插桩的原 controller 混合运行 TSan，对照用例先卡在原 POSIX timer 校准循环。把测试目标中的实际 timer/backend 一并插桩后不再卡住，但 controller 的 `named_thread_pool::start`／promise 同步报告竞争。源码中的同步使用 std::future/atomic；混合插桩看不到完整同步关系，但尚未用完整插桩证明是误报，故保留为未解决检查项，不用 suppression 掩盖。

## 接入时的边界

区块验证接入默认线程数为 0，没有发布 nodeos 开启参数或替换已有运行程序。

设计边界为：只接受本地明确列出的代码哈希、单个普通顶层 action、无 delay/上下文无关 action/扩展、非原生/非 privileged、当前 interpreter 模式。基础表逐批有界复制，未知访问回退。

成功结果在原 `apply_context::exec_one` 调用 WASM 的位置被尝试采用。先核对当前代码/输入/限制以及完整的有界读取表，再通过原 `db_find_i64`／`db_update_i64` 按日志重放。权限、交易去重、RAM/CPU/NET、action 序号、收据、undo、QC 与最终确认仍走原代码。第一版仅允许显式 CPU 的区块验证，不开放生产者采用，以免漏计私有执行 CPU。

相同原生 Savanna 语料交给串行、1/2/4 线程 validator，逐块比较完整性摘要、交易/action 收据、返回值、RAM、head 和 LIB，并确认多个独立写交易真实进入采用路径。首批结果已通过；完整矩阵及真实进程仍未完成。

尚未完成：完整边界差分、全项目插桩竞争检查、生产者调度与 CPU 计费、真实多进程互验、扩大能力时的访问审查、性能测量和最终验收。没有宣称 TPS 提升或 PX0–PX6 全部完成。
