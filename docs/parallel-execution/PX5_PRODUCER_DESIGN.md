# PX5 生产端批次与计费设计

本文记录验证端之后的具体实施方案。生产端核心已接入，6 个功能用例、542 个断言独立重复三次通过，真实生产者/旧程序互验及兼容矩阵也已三次通过。性能与受控启用结论单独记录，不由正确性通过推导。默认仍关闭，不改变链上 CPU/NET/RAM 限额，不改交易或收据格式。当前实现与证据见 [PX5 接入记录](PX5_ADOPTION.md)。

## 1. 入队与生命周期

`producer_plugin_impl::process_unapplied_trxs` 和 `process_incoming_trxs` 已有明确的队列迭代顺序。首版仅批处理这些已有待处理队列，不增加等待交易凑批的定时器，不改变新到单笔交易立即执行的路径。

主线程收集最多配置批次上限的连续普通交易，在当前待出块状态冻结有界数据。调用一个同步的 controller 批次作用域：工作池全部结束后，才逐笔调用原队列处理逻辑；原 `push_transaction`、失败处理、回调和队列删除/保留仍负责最终结算。

采用结果必须绑定交易 ID、代码指纹、批次位置和当前待出块上下文。遇到屏障、权限/依赖变化、失败、取消或不同交易，丢弃剩余结果，按原顺序串行处理；不允许把跳过的一笔试算对应到后面的交易。作用域异常退出也释放全部私有结果，不将工作池 future 存到下一块。

不同时运行普通交易试算和只读窗口。冻结和提交都在原读写线程；工作线程不得调用 controller、队列或回调。工作池不异步持有正式数据库。

## 2. CPU 计费

现有 `now - pseudo_start` 包含原签名计费调整及主线程执行。受限成功采用路径使用：

`原签名计费 + 单笔成功私有执行耗时 + 本笔正式授权/依赖核验/提交/结算耗时`。

工作池已经分别记录每笔执行开始和结束，排队与编译不在该值内。这里保留现有按运行时间的计费口径，不声称它是操作系统纯 CPU 时间或确定性 gas。线程争用造成执行变慢仍可能增加本笔耗时，与现有串行运行中的系统抢占相同。

- 入队、等其他工作线程、等前序正式提交不计入本笔 CPU。
- 失败/冲突试算只属节点内部成本；串行重跑按原方式计费，不能试算和重跑各扣一次。
- 在原授权及全部采用前置检查成功后、首次正式写入前，才补记成功试算耗时。此前拒绝或回退不补记。
- 不能把接收块 CPU 显式计费方式照搬为生产者“自填固定 CPU”。最低计费、账户/交易/块额度及主观限制继续由原事务检查。
- 补记通过事务内部一次性方法完成；调整计费起点，并缩短 CPU 剩余时间，但**不得把块的真实墙钟截止也向前扣一次试算时间**。

为区分两种截止，初始化时另保留尚未被墙钟截止截断的 CPU 截止及异常类型。补记时先检查原计时器没有失效，再停止旧计时器，以“剩余 CPU 截止”和“原块墙钟截止”的较早者重新启动，并立即执行原 checktime。undo 清除采用能力；reset 清除计费/采用字段。一笔已撤销事务不能重新使用旧能力，失败 trace 可保留本次耗时诊断。成功采用若随后资源结算失败，仍走原事务 undo，不产生正式资源用量和收据。

## 3. 出块截止与背压

开始新批次前检查原块截止。工作线程接收无 controller 指针的取消代数和绝对本地截止；排队中的任务也检查截止，不能一笔笔各重新获得完整时间预算。编译/链接仍受代码大小和实例数量上限约束。

私有阶段最多取当前剩余墙钟时间的 1/4，且不超过 50ms；还需为原路径预留“本笔客观 CPU 上限（不超过块剩余 CPU）+ 5ms”。不足这段时间时直接串行，不再试算。否则慢试算可能耗尽每一块的窗口，使同一个队首无限重试却从不接受原 CPU 超限判定。该本地试算限额不是新的链上 CPU 限额，耗尽后仍按原交易规则回退。新增 100ms / 500ms 窗口慢队首用例已在 1/2/4 worker 下三次通过。

截止后收齐工作线程，丢弃尚未采用结果，保持原队列的重试规则；不宣布 RPC 成功，不擅自删除未收录交易。不得扩大链上 CPU 总额度补偿多个核心的总计算量。

## 4. 必测验收

1. 实际采用的独立写交易包含私有执行计费；CPU 最小值、交易头上限、账户额度、块额度与主观最大执行时间均有效。
2. 块墙钟截止较早、CPU 截止较早、已超时、补记后恰好越界分别验证；显式验块计费保持不变。
3. 冲突/私有失败回退只结算一次；重复、过期、权限失败不重复触发回调，不污染下一块。
4. 队列满、部分批次耗尽、回调异常、abort/切叉/关闭之后无旧结果可采用。
5. 0/1/2/4 worker，新生产块由保留的旧 nodeos 完整验证；对照资源、收据、状态、LIB，不要求两次独立生产的实测 CPU 数值相同。
6. 保留组块、签名、恢复记录和 finalizer 的原顺序；实际测试漏块/最终确认，不把仅有吞吐的结果当作通过。

若计费或生命周期验证失败，实验开关保持关闭，修复后重测，不能以性能收益替代正确性验收。
