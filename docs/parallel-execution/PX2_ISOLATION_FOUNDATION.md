# 有界主键状态隔离基础与 SoftFloat 线程状态修复

日期：2026-10-11。分支：`feature/parallel-tx-execution`。本记录继续 [PX1 主键读取原型](PX1_PRIMARY_READ_PROTOTYPE.md)。

## 1. 当前状态和验收边界

新增的是测试专用的冻结数据副本、私有主键更新层和元数据/部分读取接口。**没有接入 controller、真实 WASM 交易 worker 或正式状态提交；PX2 最小并行交易闭环未完成。** 全入口访问审查、权限/资源/收据隔离、冲突验证、批次取消与按序提交仍是接入前置条件。

SoftFloat 的线程状态修复是实际构建配置变更，会影响重新构建的程序；并非只改变测试。它不改变舍入默认值、交易格式或链上规则，不改动 vendored 子模块源码。既有 nodeos 可执行文件和运行链尚未替换。

## 2. 本批状态层能力

### 2.1 不复制大行也能定位和查长度

`transaction_state_view` 增加 `locate_primary` 和 `read_primary_prefix`。前者只返回 ID、主键、payer、完整长度等元数据；后者最多复制调用方要求的前缀。长度为零时只查长度，不复制内容。原完整读取的严格本地预算仍保留。

这些接口还不是 WASM `db_get_i64`，不自行生成或接受合约 iterator。正式接入时仍需保留旧 host 的 iterator 校验及返回值规则。

### 2.2 明确选择、有上限的不可变基础状态

`frozen_primary_state::capture` 在串行所属线程上复制明确列出的逻辑表，分别限制表项数、主键行数和总 payload 字节。默认上限为 64 项、4,096 行、4 MiB payload；容器元数据另由表/行项数上限约束，不将 payload 预算描述为精确 RSS 上限。

这是小规模实验能力的有界数据副本，不是复制整份链数据库，也不是已经实现控制器级冻结/MVCC。捕获阶段仍要求调用方保证没有并发数据库修改。捕获后不保留任何 Chainbase 引用，后台读取不会再访问原库。

未捕获的表和“已捕获但不存在的表”严格不同：前者抛出本地不支持异常，要求整笔回退，不能将其伪装为表不存在。超限也不能被当作共识无效。

### 2.3 每笔尝试私有的有限更新层

`primary_state_overlay` 的首批能力严格限于已有主键行、长度不变、payer 不变的更新；payer 为零按原约定沿用旧 payer。新增、删除、改变长度或付款人不在支持范围，尚未实现对应 RAM/ID/表生命周期处理。

每次基础读取都保守记录整张逻辑表依赖，包括表不存在、行不存在和空范围。重复写入保留操作顺序；查询会读到本尝试最后一次写入，而不会改动其他尝试、冻结基础状态或正式数据库。

本地限制分别覆盖依赖表数、写操作数和累计写入 payload 字节。零长度写入仍消耗操作额度。任何操作异常后整个尝试失效，不能仅丢弃最后一条操作再提交之前的私有写入。封存只能成功一次，之后不能继续读写。封存结果只是私有数据，**不代表授权检查、交易计费或正式提交已经通过**。

当前没有冲突验证器。整表依赖集合只是后续验证器的输入，不是已实现的版本检测；不能只比较最终字节就声称解决 ABA、回滚或范围幻读。

## 3. SoftFloat 发现、复现和修复

访问审计发现 `libraries/softfloat/source/include/softfloat.h` 在未定义 `THREAD_LOCAL` 时将其设为空；实际 C 库编译参数也没有该定义。虽然 C++ `softfloat.hpp` 定义了 `__thread`，但不能影响已经独立编译的 C 实现。

修复前 `softfloat_state.c.o` 的 ELF 符号类型为 `OBJECT`，以下四项在多个线程间共享：

- `softfloat_roundingMode`
- `softfloat_detectTininess`
- `softfloat_exceptionFlags`
- `extF80_roundingPrecision`

仅比较线程内取得的变量地址即可安全复现，无需刻意制造有未定义行为的数据竞争。修复前该测试 40 个地址隔离断言全部失败，日志已保留。

在父仓库 `libraries/CMakeLists.txt` 中对 `softfloat` 添加 PUBLIC `THREAD_LOCAL=__thread`，使当前 GCC/Clang 工具链的 C 定义和所有消费者声明一致，避免只改声明、只改测试或混合 TLS/非 TLS 对象。子模块仍为原 `19cbea6`，没有对其直接提交或改写。

修复后四个 ELF 符号均为 `TLS`。新增测试验证默认值、1/2/4 worker 的结果一致性，以及同时使用不同舍入模式、异常标志、tininess 和扩展精度设置互不干扰。

修复前先对旧库运行固定种子 `0x5058305f464c4f41`、10,000 组 f32/f64/f128 位模式运算，保存指纹 `4281633724421848196`；修复后完全一致。指纹仅用于此固定回归语料，不是密码学安全证明或全部浮点输入的穷举证明。

**重新构建需要保持库和使用者一致**，不能把新 TLS 静态库与采用旧全局变量声明的对象混用。PUBLIC 编译定义会触发相关消费者重编译，这不是编译缓存故障。

## 4. 已运行测试和待完成回归

- 主键状态测试：33 个用例、36,563 个断言通过。包括原 18 项以及新增 15 项；新增随机差分的种子为 `0x5058325f57524954`，800 次私有更新对应 28,800 次结果/元数据/部分读取比较。
- 4 个 C++ 线程同时操作私有更新层；在这些线程运行时，主线程删除并重建原库记录，线程结果仍互不影响。这里只证明数据层隔离，**不是 WASM 交易执行重叠证明**。
- SoftFloat：5 个用例、72 个断言通过，旧语料位模式指纹不变。
- 访问审计工具：扩展后 22 个 Python 用例通过。
- 受 TLS 构建定义影响的链核心、串行 Savanna 对照和既有原生回归正在重新编译；完成前不记为本批通过。
- 本批尚未运行 ASan/UBSan/TSan、完整业务矩阵、真实并行 P2P 或 TPS 测量。

本地证据目录：`build/local-tests/parallel-overlay-20261011-q42k0b/`。包括修复前串行指纹、预期失败的隔离测试、旧库与旧测试程序归档、修复后报告及构建日志。目录不提交 Git。

另用未替换的 `e28d8313…` 旧 nodeos、独立目录且关闭所有监听器，运行原生 profile 2 创世、SIGKILL、三次脏库拒绝、重放及再次启动。最终 head 74、LIB 72；重放保留崩溃前可逆分支。公开创世资料和已最终确认账本固定保存在 `old-nodeos-fixed-blocklog.tar.gz`，归档不含测试私钥或签名配置。这是旧二进制基线/后续互验输入，尚不是新旧程序互验通过；也不替代含合约交易的黄金语料。

## 5. 审计范围补强

访问清单升级为 schema 2，新增 SoftFloat C 源码/头文件指纹，以及父级构建定义、SoftFloat 构建文件和实际 Linux x86-64 平台头。平台头位于名为 `build` 的源码目录，必须显式包含，不能和生成产物一起忽略。

当前快照范围为 737 个文件，262 项 host 注册不变，运行时批准并行入口仍为 0。机器扫描只能发现变化；例如 SoftFloat 的全局变量不会命中数据库操作正则，必须结合手工阅读和 ELF/运行测试确认。

另为 262 个具体 host 名称建立显式设计分类，不使用前缀匹配来自动批准未来新函数。分类包括：固定输入/上下文 17 项、需要跟踪的状态读取 18 项、特权屏障 11 项、嵌套/延期屏障 9 项、私有输出 12 项、局部控制/内存 9 项、需要预算和依赖复核的密码学运算 25 项、编译器内建 43 项、SoftFloat 58 项、主键/范围读取 42 项和带 RAM/生命周期的写入 18 项。

分类是隔离设计输入，`speculation_review` 仍为 `pending`、`initial_route` 仍为 `serial_only`；不能把分类覆盖当成已经实现运行时隔离。新增未分类 host 即使被写入相同指纹快照，`--check` 仍失败。尤其不能把 `recover_key/assert_recover_key` 当成无状态纯计算：现代码读取已激活密钥类型及生产者主观限制。`require_auth` 检查 action 声明，也不能取代主线程完整权限验证。

扩展 C 文件范围时额外发现原清单未包含的 POSIX timer 编译探测及 OC GS 辅助实现，已阅读并纳入指纹；未改动这两个文件，OC 仍不在首批并行能力范围。

本批还核实了以下后续门槛，尚未将其标为已解决：

| 位置 | 具体约束 |
|---|---|
| `apply_context::next_global_sequence/next_recv_sequence/next_auth_sequence` | 当前直接写正式状态；需要按原 action 次序生成提交事件 |
| `host_context::get_code_hash` | 可观察 code sequence；不能把代码序号和纯收据递增一并无条件延后 |
| `webassembly::get_permission_last_used` | 权限使用时间可观察；不能仅检查签名后忽略前序使用/权限修改 |
| `transaction_context::init/finalize` | 账户窗口、权限使用及交易 CPU/NET 用量有正式写入，不能复用为无副作用 worker 初始化 |
| `wasm_interface_impl::get_instantiated_module/current_lib/code_block_num_last_used` | 多处无锁行为依赖“写窗口没有后台交易”；新 worker 必须有独立代码生命周期/屏障 |
| `host_context::db_get_i64` | 长度查询、部分复制、iterator 校验要保持原语义，不得直接替换为全行复制 |

下一步仍是补齐访问分类及独立串行基准，建立私有 iterator 和批次身份，再进入正式冲突校验、资源/收据结算及 WASM 隔离执行。
