# 区块验证真实采用及首批差分验收

日期：2026-10-11。分支：`feature/parallel-tx-execution`。本记录不代表整个多核计划完成，也没有开放生产者并行或部署新 nodeos。

## 已实现的闭环

`controller::apply_block` 在原块首处理之后、原交易顺序位置准备有界批次。独占工作线程在不可变表副本上执行真实 WASM；全部结束后，结果交给原交易入口完成权限、undo、资源、收据和回调。

正式采用只替代原 `apply_context::exec_one` 的 WASM 计算部分。写日志经完整依赖复核，通过原 `db_update_i64` 重放；全局/接收/授权等序号在原逻辑中产生。未支持、旧状态失败、超时、取消或冲突不能直接成为共识拒绝，必须按正确前缀走原路径。写入开始后的异常不再重跑，而由原事务及块级 undo 撤销。

受限支持条件、15 个 host 和 247 个拒绝导入的隔离理由见 [访问复审](PX0_RESTRICTED_BOUNDARY_REVIEW.md)。当前 C++ 配置为线程数 0（关闭）、批次 8、代码哈希列表为空；无 CLI 开启参数。轻验证、跳过 undo 的快速回放、OC、profiling 和 Deep Mind 当前保守串行。

## 已实际通过

固定业务步骤生成 14 个原生 Savanna 区块，再分别解码进入独立数据库。不是将一侧计算的状态复制给另一侧。

| 检查 | 用例/断言 | 具体证据 |
|---|---:|---|
| 同一区块逐前缀串并行差分 | 1 / 295 | 0/1/2/4 线程；head、LIB、完整性摘要、交易/action 收据、返回值、RAM、控制台一致 |
| 非法区块撤销 | 1 / 185 | 1/2/4 线程各跑 6 类篡改：收据状态、NET、零 CPU、缺签名、WASM 失败、重复交易 |
| 快照/重启/完整检查重放 | 1 / 86 | 1/2/4 线程；恢复后继续真实采用写交易；从区块日志独立重放并比较对应 LIB 状态 |
| Savanna 分叉切换 | 1 / 113 | 撤销已采用旧分支，执行新分支；逐次比较状态/trace，旧交易去重记录不残留 |
| 本地开关及批次边界 | 1 / 33 | 空/错误白名单、轻验证保持串行；批次 1/64 不改变最终状态 |
| **合计** | **5 / 712** | **三个独立进程重复全部通过** |

在第一项中，1/2/4 线程各试算 19 笔、直接采用 11 笔、串行回退 8 笔。包含同一热点连续更新，以及旧余额试算失败但前序入账后成功的情况。部分试算不经完整串行 WASM 重跑即被正式采用，已经不是影子执行器。工作池测试另验证多模块执行区间重叠；这仍不等于测出了 TPS 加速。

非法区块测试重新计算交易 merkle 并用固定测试密钥签名，确保不是只因明显的坏区块签名在执行前被拒绝。每次检查已存在实际采用，再验证整个块恢复到原状态、异常类型与串行一致，随后同一位置的原合法块仍能通过。

## 内存与竞争检查的真实范围

- 普通 worker/pool/coordinator：32 用例、804 断言通过。
- 私有执行 TSan：30 用例、771 断言，独立重复三次通过。包含真实 WASM 越界恢复、无内存模块、外部中断和 247 个导入拒绝。2 个混合未插桩 controller 的原接口对照不在此范围；未用 suppression 隐藏该限制。
- ASan+UBSan+LeakSanitizer：32 用例、804 断言，包括上述 2 个原接口对照，修复下述泄漏后独立重复三次通过，进程退出码均为 0。
- 上述 ASan/TSan 都不是整个 nodeos 的全依赖插桩；原 Chainbase/FC/controller 的覆盖边界仍按前期记录说明。

检查确实发现并处理了问题：

1. 无线性内存的 EOS VM 页数为 -1；禁止把它转换为超大无符号 span。
2. 旧异步超时与工具信号跟踪不兼容，改为受限解释器协作式检查。真实内存异常路径仍保留并测试。
3. 当前 libtsan 不拦截 fortified `__longjmp_chk`。仅 TSan 测试目标使用 `-U_FORTIFY_SOURCE -D_FORTIFY_SOURCE=0`，生产硬化不改；真实越界用例随后通过。
4. 首轮 ASan 虽然 804 个功能断言通过，退出时仍报告旧 `IR::FunctionType::get` 缓存泄漏 934 字节/51 项。把私有类型表改为 `unique_ptr` 所有权，保持驻留期间地址和类型去重语义，并保护插入失败时的临时对象。未关闭泄漏检测；修复后退出检查通过。该文件在主仓库内，不是 EOS VM/SoftFloat 子模块改动。
