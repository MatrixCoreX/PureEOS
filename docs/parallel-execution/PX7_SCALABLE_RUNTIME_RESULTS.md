# PX7：保持 16 线程上限的可扩展运行时整理

日期：2026-10-17。分支：`feature/parallel-tx-execution`。

## 范围与当前状态

用户确认：本轮不提高线程上限，先完善架构和效率，保留未来更多线程的扩展能力。该分支在本轮之前已经允许 1～16 个并行 worker；本轮不是首次支持 16 线程。

三个目标已编译成功，82 项相关源码前后核验一致；专项及 CLI 通过。**原完整回归在第二轮核心测试失败后停止**；随后仅增加诊断的核心版三轮通过，同一 worker 程序累计三轮通过。原偶发失败未定位，不能用补测通过抹掉失败或宣称整个并行计划完成。

证据目录：`build/local-tests/parallel-scalable-runtime-20261017-GlzJ9z/`。前一批 N2 的通过结果仍属于前一版，不计入本批。

## 本批代码变化

- `parallel_runtime_limits.hpp` 集中定义本地 worker、批次、发现轮次、快照/环境 payload 和准备时间上限。控制器、协调器、线程池及 CLI 共用校验。
- 线程上限保持 16，批次上限 64；准备时间上限保持验证 500ms、生产至多 50ms。并行默认关闭、默认批次 8 均不改。
- 控制器仅对尚未完成的 sync/mixed 交易刷新发现指纹；所有 worker 返回后，最终代码目录一次性转移给采用阶段，避免每轮重复复制已完成交易的代码和输入目录。
- 新增/扩展线程矩阵和 CLI 边界检查；没有放开首次串行回退之后继续采用旧尾部结果。

## 未来扩线程的边界

1. 线程数量是本地执行策略，不写入创世、快照、收据、交易指纹或区块有效性规则。
2. 交易位置、不可变 preparation/ticket 和有序提交接口独立于 worker ID；不能把线程调度当作交易顺序。
3. 每线程独占可变 VM、内存、栈及执行上下文；共享输入必须不可变且拥有明确生命周期，worker 不直接写 Chainbase。
4. 当前大于 16 的配置必须拒绝。未来扩大上限时同步审阅固定数组、内存/缓存、取消、提交和传播能力，并扩展测试矩阵；不是简单改一个数字后直接发布。
5. 这一硬件扩展边界不恢复旧 EOS/旧链兼容任务；当前新程序自身的串行对照和恢复验证仍保留。
6. 更多 worker 不自动提高链上区块容量。发布前须确定最低硬件基线，验证较低配置可持续接收较高配置生产的热点/回退块；“支持 16 线程”不等于任意 4 核机器都能承受提高额度后的满载网络。本批未做异构服务器持续跟链测试。

## 不能由本批推出的结论

本机 4 个物理核 / 8 个逻辑 CPU。12/16 worker 的功能通过不等于 12/16 物理核的吞吐验证；编译次数、发现次数和单元测试时长不等于最终确认 TPS。本批没有提高链上 CPU/NET 配额，没有修改经济/治理规则，也没有完成 N3 冲突局部化、通用并行提交或 20× 性能目标。
