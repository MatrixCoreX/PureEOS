# PureEOS 链上短号租赁与解析计划

日期：2026-10-31

状态：**待商议的规划记录；尚未实现、测试或部署本功能。**用户最新要求先按当前已验证基线重置、测试，保留现有系统合约及旧拍卖功能。当前重置采用 12 位非系统账号并保留协议系统名称，不启用本草案的短号规则。

## 一、讨论中的产品定义

短号是由系统合约管理的**链上可租赁账号别名**，解析到一个已存在的 12 位原生账号。它类似链上的名称解析记录，不是新的独立原生账号。

示例：

```text
租约有效：abc → aaaaaaaaaaaa
到期释放：abc 不再提供有效解析，任何人都可抢注
重新抢注：abc → bbbbbbbbbbbb
```

`aaaaaaaaaaaa` 的资产、权限、密钥、合约状态和投票身份继续属于该账号。第二个租户获得短号的新租约，不获得第一个账号的资产或权限。

原生账号可以使用自己的独立密钥。链上保存公钥或账号授权关系，私钥由钱包保管。

## 二、已记录的讨论规则（整体方案待商议）

### 1. 抢注与到期

- 注册、缴租、续租、归属、转让和到期判定由链上系统合约执行。
- 租约有效条件为 `链上区块时间 < expires_at`；到达或超过到期时间即失效。
- 到期立即开放重新抢注，不设原持有人专属续租宽限期或抢注优先权。原持有人也须参与普通抢注。
- 竞争同名租约，以最终成为不可逆的链上执行结果为准，不以点击时间、后台接收时间排序。
- 新注册的租金扣款与租约建立在同一笔交易中完成，失败整体回滚。
- 到期属于逻辑状态，不依赖后台删除记录、定时交易或全表扫描。新抢注可直接替换已过期记录并增加版本号。
- 保持两个 deferred-disable 阶段启用，不使用延迟交易实现释放或续费。

### 2. 短号权限与转让

- 短号没有独立的原生 `owner/active` 权限或公钥控制器。
- 持有人不能将短号改成公钥、赋予独立原生权限，或把租赁名称转换成永久原生账号。
- 租约持有人必须是链上已存在的 12 位原生账号；转让接收方也必须满足此条件。
- 转让由当前持有人签名授权，短号归属和解析绑定一起转到接收账号。
- 不提供与归属分离的任意绑定修改入口，避免旧持有人保留控制权。
- 转让保持原到期时间，只转移剩余租赁权；原账号资产、密钥及原生权限不随之改变。
- 过期后，原持有人失去转让和专属续租权。旧租约签名或旧版本请求不得操作新租约。
- 12 位原生账号自身仍可正常更换密钥、管理权限；系统合约使用该账号当前有效授权校验操作。

### 3. 查询和使用

- 解析结果必须同时校验租约有效期、当前持有人及记录版本，过期记录不得作为有效收款目标返回。
- 钱包和浏览器从链上读取映射，签名前显示实际原生账号。PureHistory 提供索引、查询和展示，不能决定权属。
- 普通 EOS 格式交易仍使用实际原生账号。客户端支持短号时，先解析再构造交易。
- 如增加按短号付款的专用系统合约操作，在执行时校验有效期、预期持有人和版本，并原子完成解析与付款。
- 不能描述为现有所有钱包、SDK、合约或原生账号字段会自动识别短号。相应客户端适配须单独完成。

### 4. 新链规则

- 从新链初始化开始采用新规则，不做旧拍卖迁移。
- 不设计旧竞价退款、旧中标领取权、祖父条款等迁移分支。
- 新短号业务去掉原拍卖的加价、14 天等待和每日成交限制；租赁开放时间由新链初始化配置明确。
- 必要系统保留名称在创世初始化中明确列出，和普通租赁名称区分。
- 除明确的协议保留例外，原生账号创建路径须防止用户通过原拍卖领取或其他创建入口绕过租赁规则，永久占用新租赁短号。

## 三、建议初版参数与待定事项

以下是设计建议，尚不作为已确定的链上费率或最终接口。

| 项目 | 初版建议 / 待定内容 |
| --- | --- |
| 名称范围 | 1–11 位、无点顶级短号；字符集沿用 EOS 名称规则。子名另行设计 |
| 租期 | 建议每年按 365 天，可选 1–5 年；需确定最长预付期限 |
| 租金 | AIC 最小单位整数计价，按名称长度分档；具体价格待定 |
| 租金账户 | 建议进入 `eosio.fees`，不增加代币发行量，不改变节点奖励规则 |
| 续租 | 有效期内从原到期时间延长；过期后使用普通抢注流程 |
| 价格更新 | 通过现有治理流程生效，设置公开生效时间；不追溯修改已付款租期 |
| 付款保护 | 交易携带最高可接受费用和预期价格版本，防止报价变化导致超额扣款 |
| 转让附加费用 | 待定，不擅自加入新的收费项目 |
| 提醒 | 钱包/浏览器可提前提醒；提醒失败不改变链上到期规则 |

租期计时必须与奖励的 364 天计提年分开定义。停链恢复后的时间边界须明确并测试，不在实现中暗加到期宽限或自动延期。

## 四、合约实现草案

### 1. 数据

建议建立租约表，至少包含：

- 短号：唯一主键。
- 持有人：已存在的 12 位原生账号，同时作为解析目标。
- 到期时间。
- 单调增加的记录版本，用于防止旧请求、旧签名及旧缓存作用于新归属。

另设租金配置表，记录长度档位、整数费率、价格版本、可租期限、开放状态和系统保留名称。RAM 付款、记录复用及版本溢出处理须在实现时明确。

### 2. 操作

拟定注册、续租、转让、治理配置及只读解析接口，最终 ABI 名称在开发时确定。

- 注册：校验名称、保留名单、12 位持有人、授权、可用状态、期限和费用。
- 续租：仅适用于仍有效的租约；不改变持有人。续租付款授权细节在 ABI 设计中明确。
- 转让：校验当前持有人、租约版本、未到期状态和接收账号，再整体变更归属与绑定。
- 解析：按当前链上状态返回有效持有人、到期时间和版本；对过期名称返回不可用。
- 配置：沿用现有系统治理授权，不另设后台权属管理权限。

## 五、新链和测试脚本准备

- 后续重置原保留服务器上的测试链，使用独立的新数据目录和新链 ID；保存旧链数据、脚本和全部历史测试证据。
- 新版脚本生成的 BP、节点、普通用户及测试合约原生账号统一为 12 位。例如 `bpnodeaaaaaa`、`testusaaaaaa`、`testctaaaaaa`。
- 角色通过统一账号清单引用，避免脚本继续硬编码 `nodea`、`alice` 等短身份。
- `eosio` 等协议固定系统账号保留必要名称，列为明确例外。
- BP、finalizer、投票、治理、资产和签名身份始终使用永久账号；租赁短号单独作为名称记录测试。
- PureHistory 为新链隔离索引、数据库及缓存，更新链 ID 和连接配置；浏览器同步新链信息，避免混入旧链历史。
- 所有节点保持并行模式及现有硬件下限。保留 CPU16、当前开发预设 NET4MiB（吞吐验证中）、P2P64MiB、1GiB 队列、RAM64GiB＋1024/块、单选投票、轮换、维护、处罚、10%/90% 资源划分、精确 1% 奖励和减半及治理规则。
- 本文记录规划，不表示已重置链、已生成新版脚本、已启动压力测试或已创建服务器。

## 六、验收清单

| 范围 | 必须验证的结果 |
| --- | --- |
| 抢注竞争 | 同名并发仅一个成功；失败交易不扣租金 |
| 时间边界 | 到期前可续租；到期时失效；到期后任何人可抢注 |
| 旧持有人 | 过期后不能续旧租约或转让；旧签名不能操作新归属 |
| 转让 | 仅当前持有人可授权；接收方必须为已存在的 12 位账号；到期时间保持不变 |
| 权限模型 | 公钥不能作为短号持有人；原生权限修改不能把短号变为独立账号 |
| 资产隔离 | 转让、到期及重新抢注不改变原账号的资产、密钥和权限 |
| 解析 | 过期结果不可用；版本、缓存和签名时的目标检查正确 |
| 费用 | 精确整数计价、报价版本、费用上限、溢出及原子回滚正确 |
| 原生入口 | 不能通过创建账号或原拍卖入口绕过租赁规则 |
| 新链接入 | BP 和测试身份均为 12 位；RPC、PureHistory、钱包、浏览器链 ID 一致 |
| 链运行 | 重启、同步、分叉回滚、最终性及停链恢复后的租约判定一致 |
| 基线保持 | 现有投票、治理、轮换、奖励、资源和禁用延迟交易规则不回归 |

实施顺序：规则和费率配置确定 → 独立系统合约版本 → 客户端与 PureHistory 适配 → 远端资格测试 → 新链初始化与联合验收。通过资格测试后再纳入开发基线。
