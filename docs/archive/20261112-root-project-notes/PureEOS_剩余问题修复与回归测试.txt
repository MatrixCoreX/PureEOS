二、已定位的问题和修改
1. Savanna 集群测试夹具越界
   node_t 构造期间，vector::emplace_back 尚未把节点加入 _nodes，就调用了
   按索引访问 _nodes 的同步函数。新编译器的边界检查使这项旧越界暴露。
   改为构造时只安装回调，全部节点构造后由集群统一同步；重启时仍自动
   从其他节点追块。新增关闭/重开一个节点后追上区块并恢复最终确认的测试。
   文件：PureEOS/unittests/savanna_cluster.cpp、savanna_cluster_tests.cpp。

2. 交易在暂停计费期间可能丢失中断
   WASM 首次加载/编译会 stop/start 计费定时器，旧中断只对 running 生效，
   暂停中收到中断，或中断后又暂停，会让请求丢失。固定延时的旧测试受机器
   负载影响，有时通过，有时卡在无限循环；单次通过不能排除这个竞态。
   增加中断序号，由每笔交易记住起始序号；暂停/恢复保留请求，下一笔交易
   重新建立基准。定时器恢复时重新通知 watchdog；不更改 CPU 额度、区块
   截止时间或共识规则。POSIX、ASIO、kqueue 后端接口同步调整。
   外部取消和内部 OC tier-up 重试通知分开：前者保留，后者在重试时清除；
   两者同时发生时不能把外部取消也清掉。专门增加内部重试/外部取消交错测试。
   新测试覆盖首次启动前、运行中、暂停中、重复恢复、下一笔不继承、回调
   交付，以及 200 次并发暂停/中断竞争。真实 WASM 冷启动中断测试保留，
   还会在中断后执行正常交易，检查下一笔交易和缓存 WASM 能继续工作。
   文件：PureEOS/libraries/chain/include/eosio/chain/platform_timer.hpp、
   transaction_context.hpp、wasm_interface_private.hpp；libraries/chain/transaction_context.cpp、
   platform_timer_posix.cpp、platform_timer_asio_fallback.cpp、
   platform_timer_kqueue.cpp；unittests/platform_timer_tests.cpp、checktime_tests.cpp。

3. 新增协议描述没有进入独立摘要校验
   原生成器只解析注释形式的预映像，漏掉 PUREEOS_ROTATION_CONTEXT 的
   字符串形式预映像。现在两种形式均由 Python 独立计算 SHA256，再和 C++
   定义比较，并检查覆盖数量、缺失和重复名称。没有修改已定义的协议摘要。
   文件：PureEOS/unittests/gen_protocol_feature_digest_tests.py、
   test_gen_protocol_feature_digest_tests.py、CMakeLists.txt。

4. Deep-Mind 预期日志仍是增加轮岗协议特性前的版本
   新增一次协议预激活交易及一次激活事件，导致区块 3 及后续摘要、引用、
   序号和资源使用统计改变。对照确认权限、RAM、ABI 导出、出块时序记录
   不变，更新固定日志，继续逐行比较；新增文件打开检查和另存实际日志选项。
   文件：PureEOS/unittests/deep_mind_tests.cpp、deep-mind/deep-mind.log。

   首轮回归又暴露出同类的历史兼容性夹具问题：verify_block_compatibitity
   原来自动启用所有新特性，不能再复现旧参考链。这里不更新历史区块、
   快照和参考 ID，而是单独固定其 25 项历史协议清单；仍要求精确 ID、
   旧日志重放和旧快照同步通过。其他集群测试仍启用全部当前协议特性。
   文件：PureEOS/unittests/savanna_cluster.hpp、savanna_misc_tests.cpp。

5. 测试安排和合约选择
   节点公钥测试原来是在机器繁忙时触发 20ms 上限；初步单独复测通过。
   ABI、公钥、checktime 计时敏感套件改为 CTest 串行，仍使用原执行限制。
   API part1 的测试框架看门狗设为 10800 秒，容纳未优化解释器构建；这不是
   链上交易 CPU 限制。多节点 CTest 优先使用当前完整轮岗合约目录，避免
   配置了完整版本却仍测试旧资源版本。
   文件：PureEOS/unittests/CMakeLists.txt、tests/CMakeLists.txt。

   注意 RUN_SERIAL 只约束同一个 CTest 调度器，不能阻止另一条独立 CTest
   命令同时占用 CPU。最终版本首轮重复测试与其他长测并行时，checktime
   的一项墙钟断言失败：预期的 deadline_exception 已抛出，但总耗时
   127740us 超过断言的 125000us。原始失败证据保留在
   critical-repeat-concurrent-load.log/.xml，不能删除或计为通过。
   后续再次发现独立执行也会因加载时长误报，最终修复断言对象见第 7 条；
   保留数值上限，不跳过测试，也不修改链上执行时限。

6. 大签名 ABI 超时后的十六进制回退开销
   首轮完整矩阵 157/159 通过，原来的 19 个问题目标全部通过；两种 VM 的
   abi_large_signature 仍超过 51ms。单独运行也出现 71–103ms，CPU 使用
   接近 100%，因此不能仅解释为其他测试并行。fc::to_hex 逐字节做两次
   字符串追加；回退同时填写 data 和 hex_data，对大签名重复承担该开销。
   改为一次分配目标长度后直接填充，保留小写格式、每字节两位、前导零
   和所有字节值；增加长度溢出检查。新增独立格式参考、空输入、边界长度、
   256 种字节及 256KiB 数据往返测试；ABI 的原 51ms 断言保持不变。
   文件：PureEOS/libraries/libfc/src/crypto/hex.cpp、unittests/misc_tests.cpp。

7. 计时测试错误地用总墙钟时长约束不含加载时间的 CPU 预算
   串行复测仍发现冷加载后总时长 163724us 超过 150000us，但预期的链上
   CPU 额度异常已正确触发。原测试把明确“不计费”的 WASM 加载及异常
   返回开销一同算入执行预算，不能用它判断暂停计费逻辑是否正确。
   改为从异常结构化数据读取 billing_timer，检查原来的 125/150/250ms
   上限，并增加 24999/25000us 的实际计费下界检查；区块截止测试另检查
   deadline-start 不超过原请求的 15/75ms、抛出异常时确实已到截止时间。
   因而能直接发现“加载暂停错误地延长区块截止时间”，不依赖特定机器
   必须在 35ms 内加载完大 WASM。冷缓存、真实无限循环、异常类别及原因、
   编译后缓存和正常交易恢复检查均保留。没有修改运行时代码或链上限额。
   文件：PureEOS/unittests/checktime_tests.cpp。

8. 真实多节点测试客户端的分页和最终确认
   新版首次四节点联测在第 4 个节点投票后的排名校验失败，进程已正常停止。
   在独立、无出块密钥及无 P2P 的数据副本上核对，LIB 981 已包含 nodec
   的投票，四个节点的整数票数及总和正确。强制分页也能完整读取四个节点。
   原脚本忽略 get_producers 的 more，且失败前没有保存原始 RPC 页，因此
   不能事后断言那次观察失败的唯一原因；分页处理缺失是明确问题。
   现在跟随游标取全页，允许限时产生的空页有界重试，拒绝重复行及跨页
   总票数变化，不在客户端重新排序掩盖 RPC 顺序问题；断言前先保存实际页。
   同时修复另一处确认漏洞：processed.block_num 只是预执行高度，不能用
   LIB 到达该高度代替交易确认。现在按交易 ID 在真正不可逆区块中查找
   executed 收据，记录实际区块 ID、高度、观察时 LIB 和原预估高度。
   新增 9 个 Python 用例覆盖延后入块、字符串收据、失败状态、读失败重试、
   未包含交易超时、分页顺序、空页、重复生产者和总票数变化。
   文件：PureEOS/tests/pureeos_single_choice_local_test.py、
   pureeos_multinode_local_test.py、pureeos_local_test_harness_test.py、CMakeLists.txt。
   后续在重负载并行时，部署大系统合约触发原来的 150000us 交易 CPU
   限额，交易被拒绝；保留 four-node-deployment-cpu-load 日志。此处不提高
   链上限额，真实多节点最终验收安排在计算密集套件结束后独立执行。

安全记录来强行恢复。已经丢失且没有备份/对等节点的旧锁定区块不能凭空恢复。
