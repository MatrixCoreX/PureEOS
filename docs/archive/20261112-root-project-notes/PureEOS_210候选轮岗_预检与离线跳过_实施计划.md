## 1. 最新要求：先用人话说清楚

1. 初始候选名额上限为 210，从中按顺序轮流安排最多 21 人实际出块。支持从一个节点起步。
2. 不要求现任节点检测新人是否开机，不要求检测回执、投票批准或候选在线响应；候选按规则直接进入名单变更流程。注册和密钥合法性检查仍保留。
3. 每次只增长或替换一个席位，必须完成真实共识交接，不能一次换入整组陌生节点。
4. **正式生效名单不足 21 人：不累计黑名单次数、不因零出块拉黑。** 不出块的账号没有新增节点奖励；本次不另加离线罚款或资产冻结。
5. **正式生效名单满 21 人：保留连续三轮零出块自动拉黑的设计。** 不需要现任节点判断或举报，依据链上实际排班和最终确认产出计算。
6. **所有阶段零最终确认有效块＝零新增节点奖励。** 不因排名或候选身份发放无产出备用奖励。资金沿用原 EOS/Antelope 方案；有产出者的按块/按票分配，按文首最新确认与待核对边界处理。
7. **候选上限从 210 起，以每四年为一段线性增长，周期末达到该周期起点的两倍；名额逐步开放，不在到期时跳增。** 目标是让更多合格候选获得轮岗机会。本版按“候选名额增长、同时出块仍最多 21 人”理解；不把候选扩容等同于共识人数扩容。
8. **本轮同时实现一票一投：1 个用于投票的锁定核心 Token＝1 票，每个账号最多直接选择一个候选，禁止代理和时间放大。** 不是一账号一票，也不是钱包中可随意转走的余额自动计票。票数决定候选资格和初始排队位置，不能给零产出者带来备用奖励；有产出者是否保留原票奖另按最新奖励口径核对。
9. 一并实现已确认的 REX 规则：买入/质押转入 REX 前直接选一个有效候选，持有 REX 期间允许原子改投、不能清空选择；全部实际卖出并结清票权后才可撤票。纯资源租用不要求投票。
10. **取消代理投票及系统原生“代理票池”也是本轮明确交付项**：不再登记代理、不接受委托、不累计代理票权，不允许多个账户把票权集中交给一个代理统一投票，不保留可用旁路。用户已明确接受场外买票卖票无法靠本改造杜绝，验收目标是关闭系统原生票池，不是证明链外无交易。“票池”不指 REX 资金池，REX 买卖和资源租赁保留。
11. **取消固定备用节点制度：所有当期合格入围者都须轮岗出块。** 排队等待是同一轮岗身份的暂时状态，不是可以只领票奖而不履职的备用身份。实际出块后离岗，不追缴已赚收益；没有到达本人正式窗口前不处罚。

以下区分用户明确要求和设计建议：本轮一票一投及 REX 投票约束、不足 21 人不拉黑、零块零新增奖励、取消可用性预检和固定备用身份、四年翻倍且线性逐步增长、永久轮岗禁入已明确；四年的具体时间口径及有产出者的奖励分配细节仍待确认。投票细则见第 3.4 节，连续三轮的精确定义见第 5 节。

## 3. 候选上限每四年翻倍，与公平分配

### 3.1 扩大的是候选名额，不是保证实际在线人数

- `C(t)` 表示时刻 t 的候选上限，起始值为 210；实际注册且合格的候选不足上限时，按实际人数处理，不造假补足。
- 正式出块/最终确认成员仍最多 21 人，等待轮岗的候选不因为扩容自动变成 finalizer，不要求全体候选全连接或共同确认每个块；不再设置固定备用节点身份。
- 超过当期上限者暂不进入当期队列。满 21 阶段出现黑名单时，先取当期前 `C(t)` 的排名快照，再在轮岗时跳过黑名单，不擅自补入第 `C(t)+1` 名；用户投票及后续快照可以改变入围者。
- 起始时“第 211 名不入围”只适用于 `C(t)=210`，不再是永久边界；上限增长后按新边界验收。
- “四年翻倍”不改变代币发行、奖励池总额、RAM/PowerUp/REX 资金流向。

### 3.2 已确认增长方式：每个四年周期内均匀开放名额

用户已明确选择线性逐步增长，取消四年到期一次跳增的备选。结合此前“每四年翻倍”，按每四年一段的分段线性计算，增长公式固定，不开放给 BP 临时切换。

```text
C0 = 210
T0 = 新链规则初始化时记录的链上 slot（当前实现；不是原始创世时间，迁移另定）
P  = 1461 × 86400 × 2 slot（当前实现采用的固定周期；不等同所有公历四年）
Δ  = max(0, 当前共识 slot - T0)
e  = floor(Δ / P)
r  = Δ % P

C(t) = C0 × 2^e + floor(C0 × 2^e × r / P)
```

| 相对增长起点 | 分段线性上限示例 |
| --- | --- |
| 第 0 年 | 210 |
| 第 1 年（首周期的 1/4） | 262 |
| 第 2 年 | 315 |
| 第 3 年 | 367 |
| 第 4 年 | 420 |
| 第 8 年 | 840 |
| 第 12 年 | 1,680 |

按名额取整，链正常推进时随着时间逐个开放，不存在半个节点。首个四年平均每年增加 52.5 个名额，第二个四年平均每年增加 105 个名额，第三个四年平均每年增加 210 个名额；每段内部匀速，周期边界没有突然成倍跳增。若全程固定每年增加 52.5 个名额，则第八年只能到 630，不能满足每四年翻倍，所以本版明确采用分段线性而非全程同一斜率，也不是连续指数复利。

容量由共识时间实时算出，不按年度批量放出 52/53 个名额；表中年度数值只是检查点。节点正常运行时开放单个整数名额；长期停链后恢复可能一次观察到多个已到时间的名额，这不同于设计为四年到期集中翻倍，且不能据此批量更换实际出块名单。

实现要求：只使用确定性链上时间，不用本机时钟或定时脚本；用整数与宽乘法中间值，检查溢出及长期最大可支持上限。固定天数周期与公历四年并非永远相同，不能未说明就将两者互换。容量增长在链恢复后依共识时间计算，但停链期间不自动执行轮岗，更不能追算一批离线处罚。

### 3.3 公平的关键是队列与计酬，不只是名额翻倍

1. 当前仍合格的候选保留队列先后和扫描游标；排名刷新、扩容和重启不把队列重置回榜首。
2. 新入围候选按固定规则加入队尾，不能让高票者每次快照都重新插队；投票决定是否入围，不增加单块奖励权重。
3. 正常轮岗的停留/轮换节奏对同类节点一致；故障替换单独处理，不能由现任主观挑选谁长期占席。
4. 同一结算期有效块数量相同，奖励相同；不因为节点早加入、排名高或账号多，就增加每块权重。
5. 增加候选名额有利于让更多账号获得机会，但不保证更多独立运营者，也不保证所有人收入相同。网络故障、漏块和资格变化都会影响实际所得。
6. 在奖励总额、轮换规则及其他条件近似不变且候选都正常履约时，候选增多意味着个人平均轮岗频率及长期奖励份额降低；扩大的是覆盖面，不是凭空增加总奖励。

**治理边界：** 本次只扩大轮岗候选上限。现有开发者升级的 14 天公示、前 210 合格候选否决名单及其门槛不自动扩大到 420/840 人。代码必须拆分“轮岗动态上限”和“治理上限”，不能修改一个共享常量而暗改治理；若将来要求两者联动，另行确认。

### 3.4 本轮必须一起实现：一票一投完整闭环

#### 3.4.1 票数来源、唯一去向与排序

```text
voting_balance(owner) = 该账号拥有的 CPU 自有质押
                      + 该账号拥有的 NET 自有质押
                      + 该账号已按确定性规则结算的 REX 核心 Token 等值 vote_stake

每个账号的投票目标数量：0 或 1（持有 REX 时必须为 1）
选择一个候选：全部 voting_balance 只计给此候选一次
未选择候选：已分配票数为 0
```

- 对用户按 `1.0000 TOKEN = 1 票` 表达，内部使用核心 Token 的 `asset.amount` 最小精度整数，不使用账户数量、时间乘数、浮点权重或 REX 份额数量直接当票数。
- CPU/NET 票权按资产拥有者及 `delegatebw` 的 `transfer` 所有权语义计算，不能给付款人与资源接收者各算一遍。REX 租赁、续租、续租储备、PowerUp、RAM、普通液态余额及尚未买 REX 的 fund 不生成此类票权；不能从混有租用资源的 `user_resources` 表反推拥有者余额。
- 质押增加/减少、解押时扣票、退款再质押、REX 买卖及成交结算，均在对应状态转换中按净额同步唯一候选票数。CPU/NET 转成 REX 时先扣原路径、再加新路径，不能重复计同一份本金；最终领取退款时不能再扣一遍票。
- 改投从 A 到 B 时，在同一 action 中扣 A、加 B 并更新本人记录；失败全部回滚。重复投同一人只应用真实余额差额，不能重复加票。100 Token 拆为十个账号，总票权仍只能是 100。
- 首次排名按整数总票数降序，同票按 `name.value` 升序；合格普通候选要求正票数，原生创世启动例外单独处理。初始队列按该排名建立；后续仍保序，新入围者入队尾，不因票数刷新插队。
- 新投票目标须具备规定的注册和密钥资格，但不要求已有正票数、已进前 `C(t)` 或已在岗，避免新候选永远拿不到第一票。轮岗黑名单作为独立入场限制，不通过清票、自动改投或吞掉历史票数处理。

#### 3.4.2 所有入口统一约束，不能只改客户端

保留 `voteproducer(voter, proxy, producers)` 参数形状可以减少接口改动，但合约必须拒绝非空 `proxy` 和超过一个候选的列表；不持有 REX 时允许空列表撤票。本人授权选择目标，不能保留 `b1` 等允许系统代用户投票的特殊入口来绕过所有者授权。

`update_votes`、`update_voting_power`、`propagate_weight_change`、`voteupdate` 及其他内部调用统一经过整数差额记账。新制度不提供可用的 `regproxy` 注册/注销代理业务：可移除 action，或仅保留始终返回“代理投票已取消”的兼容拒绝入口；两种方式都不得继续建立或转发委托。历史代理状态只能通过另行批准的版本化迁移处理，不为此留下生产中的代理登记功能。`voteupdate` 只能校准真实余额，不能因时间过去增加票数，不能替用户选择目标或清空选择。

`last_vote_amount`（拟定整数字段）记录上次实际分配余额，候选总票数、全局已分配票数与索引一并整数化并校验上下溢。旧链激活量若仍需保留须独立维护，零余额预选不能产生激活余额；原生启动和轮岗不应重新被旧 15% 激活门槛卡住。

#### 3.4.3 REX 买入/持有约束同时交付

1. `buyrex(from, ...)` 检查份额拥有者 `from`，`unstaketorex(owner, receiver, ...)` 检查拥有者 `owner`，不是资源接收者。资产变更前确认本人已直接选择唯一有效候选，所有新增份额入口共用私有检查。
2. 允许无质押/无 REX 的账号由本人授权创建零余额投票记录并预选候选，RAM 由本人承担；例如同一交易 `deposit → voteproducer → buyrex`。零余额预选不凭空给候选加票。
3. 以完整 `rex_balance.amount > 0` 判断持仓，覆盖未成熟、成熟、储蓄及未成交卖单；不能仅看 `vote_stake` 舍入值或是否提交了卖单。持仓时禁止空投票和代理，允许一次 action 原子改投另一个有效候选。
4. 部分卖出、仅挂全额卖单不能撤票；全部份额实际卖清且已成交卖单的票权差额正确结清后，才允许撤票。可以保留个人 fund 或零余额表行，不强制先提现/删表。
5. `fill_rex_order/runrex/update_rex_account/update_rex_stake/updaterex` 及自动买入储蓄、成熟卖出路径必须统一：卖单成交改变份额时及时反映票权，待结算 `stake_change` 只能消费一次，不能本人后来调用时再次扣票。内部 helper 不得递归触发投票刷新造成重复记账。
6. 所投候选后来注销或失效，不自动代投、不清空用户选择，不阻断 REX 的正常成熟、卖出、退款和已成交结算。再次买入前须改投有效候选；内部退出记账不能套用“新买入目标必须有效”的门槛，也不能让一个失效目标卡住整个 `runrex` 批次。
7. `deposit/withdraw` 个人 fund、纯 `rentcpu/rentnet` 和租单管理本身不要求投票；成熟/储蓄状态移动不解除真实持仓约束。REX 收益仍按其资产规则分配，不能因为选择某个候选就给该候选分走持有人的收益。

REX 收益入池会影响 Token 等值，当前有惰性刷新路径。本轮必须明确并验证统一确定性的估值/刷新与排名快照口径，防止仅主动调用刷新者按新估值、未刷新的账户长期按旧值参与不一致排名。若采用分批刷新，需要冻结估值上下文、处理期间余额变化并在快照完整后启用；不能在每块无界遍历所有持有人，也不能把未刷新的账户简单算成零票。只删时间放大、不处理这项一致性，不算完成投票改造。

#### 3.4.4 和轮岗、治理、奖励一次性对齐

- 轮岗前 `C(t)` 和升级治理前 210 名使用同一套新的整数票数及同票顺序，但各自保留资格特例和上限。新规则会改变未来排名和未来否决名单的成员，这是计票改变的正常结果；已冻结的升级否决名单不得追溯重算，14 天公示及否决门槛不变。
- 从表字段到二级索引、ABI、RPC、CLI、测试夹具都需适配。当前 `get_producers` 硬编码浮点二级索引，不能只改合约表却让查询回退成 active 21 人/零票结果；大整数通过无损表示传递，前端展示百分比不能再参与共识排序。
- 零产出者不能因票数得到节点奖励。2026-10-05 提出奖励沿用原 EOS/Antelope 方案后，有产出者是否保留原 per-vote 分配尚待核对；整数票权重构不能偷偷决定此分配规则，更不能让余额更新 helper 恢复无产出备用奖励。
- 新链用版本化整数表/索引；已有链不能把旧 `double` 二进制直接解释成整数，也不能随意把多选/代理余额算给第一个候选。迁移规则、历史 REX 无投票持仓和旧客户端兼容须另行明确；不擅动旧表、旧 WASM 测试资产或正式链。
- **交付门槛：投票、CPU/NET、REX、候选队列、增长、治理排名读者及零块零奖励必须完成同一版本的集成验收。不得只交付一个限制列表长度的动作，或将票权和 REX 适配推到下一轮而宣称本轮完成。**

#### 3.4.5 取消系统原生代理票池：范围与买票卖票边界

用户已确认本轮目标是取消系统原生代理投票聚合功能，接受场外买票卖票不能彻底杜绝。REX 资金池、用户合法资产托管及普通账号权限功能不是此处要删除的“票池”；不能为宣称全面反买票而擅自扩大改造范围。

1. 合约拒绝所有非空 `proxy`，包括本人手工构造交易、旧钱包/CLI、REX/质押内部更新等路径；代理账号不能替多个持有人统一选候选。
2. 新整数票权模型不再依赖 `is_proxy`、`proxied_vote_weight` 或递归传播；不能只隐藏前端按钮而保留后台累计票权。若为旧表解码保留字段，它们也不能重新参与新制度计票。
3. 所有选择、改投与撤票必须满足票权拥有账号自身的链上授权；公开的确定性余额刷新不等于获准替用户改票。候选/开发者/BP 身份不授予代用户投票权限。
4. CLI/钱包适配移除或禁用代理登记、注销和 `voteproducer proxy` 入口，批量 approve 多个候选的旧逻辑必须改成明确的唯一选择/原子改投；直接调用合约仍须受到同等限制。
5. 验证拒绝代理的交易原子回滚，不能失败后遗留委托标记、余额扣减、候选加票或 REX 买入。旧 proxy 存量迁移不自动把所有票判给旧代理或其偏好的候选。

取消代理减少了系统原生聚票/代投交易渠道，但**不能保证杜绝场外买票、交易所托管集中控制、共享密钥或普通账号权限委托带来的代操作**。一票一投限制同一份锁定 Token 重复计票，不是现实身份识别，也不是一人一票。这里不削弱普通账号自身的权限管理/合法多签，不擅自监控链外支付或增加资产罚没、实名、人工审查与惩罚投票者功能。

## 4. 直接接入和安全轮岗

### 4.1 不做在线预检，但仍检查链上合法资格

- 保留注册有效性、出块签名授权、BLS 注册密钥及已有 PoP/密钥合法性、账号映射与当期候选资格校验。
- 不新增 `subready`、`subwitness`、在线证书、ping 检测、见证阈值或现任批准动作；候选不需要额外提交“我在线”证明才能入场。
- 节点运营者仍需自己启动、同步并配置签名器；P2P 预连接和本地检查只是运维功能，不能成为他人控制的链上准入许可。
- 普通共识验证仍然存在。“不由现任预检”不等于删除合法区块验证、共识确认或保证抵抗交易审查。

### 4.2 单席交接

1. 轮岗状态机根据当前容量和持久化队列选下一位合格候选，跳过已在岗或处于黑名单的账号；没有候选则不提交空名单。
2. 不足 21 人时按既定扩容规则每次最多增长一人；满 21 人时正常轮换每次最多替换一人。不一次性把很多健康节点换成未知候选。
3. 冻结本次目标账号、密钥和资格上下文；提交前重新核对资格，协调密钥变更与其他策略更新。
4. 提交匹配的 proposer/finalizer 目标，查询真实 active/pending 状态，等待合法生效。`set_proposed_producers()` 的返回值不能当作实际生效版本。
5. 提交后不能通过改模型字段假装回滚策略；旧成员按实际生效策略继续承担职责，交接完成前不开下一次正常轮岗。
6. 满 21 人时进行入场观察。建议观察新人连续三次完整本人窗口；出现未解决的零出块故障，暂停下一次正常换人，优先等待恢复或处理故障席位，防止不断积累离线成员。具体放行条件须在实现前固定。
7. 不足 21 人时，不通过“三轮失败”追加自动黑名单或等效的离线惩罚；合法注销、原有资格变化和正常策略交接仍按相应规则处理，不把它们混成离线拉黑。

没有在线预检意味着：注册合法但服务器未启动的候选也可能进入生效名单。要如实承担由此带来的漏块和小规模启动风险，不能仍沿用旧稿“提前过滤未开机候选”的承诺。

## 5. 人数门控与满 21 人连续三轮零出块黑名单

### 5.1 人数看正式名单，不看注册数或自报在线数

`k` 取执行上下文中实际已生效、映射一致的 proposer/finalizer 成员数；策略尚在交接、身份不一致时不开始新的完整处罚窗口。

| 正式生效人数 | 零出块处理 | 节点奖励 |
| --- | --- | --- |
| 1～20 人 | 不累计黑名单次数、不因零出块新增黑名单 | 只计最终确认有效块；零块零新增奖励 |
| 21 人 | 对正式排班连续三轮零出块按固定规则计数和拉黑 | 同上；黑名单不代替实际出块记账 |

候选池是 210、420 还是 840，不影响这个 21 人开关。21 人正式名单中有一人关机，仍然是 21 人名单，只是 20 人实际在线，不能因此自动关掉处罚。

从不足 21 人增长到 21 人时，所有人从新阶段第一个完整可观察窗口开始计数，不追罚之前的漏块。若以后依法变为不足 21 人，则关闭新增处罚、清除未完成的连续计数，不在再满 21 时补记；已确认的永久黑名单不因人数下降而解除。未上岗的排队候选没有本人正式窗口，不计零出块故障。

### 5.2 一轮是什么，怎样计到三轮

1. 一次本人轮值窗口是当前排班中连续归属该账号的 12 slot，按当前 0.5 秒 slot 为约 6 秒。必须完整，不从任意时刻截取 6 秒。
2. 窗口结束且最终确认范围覆盖该窗口后：该账号有效块数为零，连续计数加 1；至少一个合法块最终确认，连续计数归零。
3. 连续第三个本人窗口零出块，原子记录第三次证据并进入轮岗黑名单；第一次和第二次不提前踢掉该人再等待下次重新入场。
4. 本版将用户“三轮不出块”解释为连续三个完整本人窗口，不是累计三次重新入场，也不是漏三个块。若要改为累计制，须另行明确，不能把两种方案混用。
5. 21 人名单循环为 `21 × 12 × 0.5 = 126 秒`，三个完整名单循环约 378 秒（6 分 18 秒）；实际从入场到第三个本人窗口结束取决于排班位置，并另加交接/最终确认延迟，不承诺固定 18 秒或固定 378 秒就完成拉黑替换。
6. 计数绑定账号、真实策略/调度区间及窗口游标，每个窗口只计一次。重放、重复回调和重复区块不能重复加次；改钥和快照更新不能主动清零既有计数。策略变更打断的不完整窗口不算失败，密钥变更需与观察/交接协调，不能无限切换来逃避观察。

只漏部分块、不连续三轮全空的节点不触发本项黑名单，但只按实际产出拿钱。不能声称该规则可以处理一切低出块率行为，或证明物理机器确实关机。

### 5.3 暂停、误判和安全生效

- 所有处罚依据确定性最终确认的历史，不直接采用某个 nodeos 的本地 LIB、RPC、到票时间或网络观察。未确认事件仅暂存，分叉撤销不留下处罚。
- 全局出块/最终确认停顿超过固定保护阈值 `H` 时，暂停处罚观察；恢复后重新开始完整观察，不把全链停顿期间多个错过窗口追算为每人三次。`H` 的定义和值必须压测后固定，不能由 BP 自报。
- 正常单个节点漏块应可计数；全链停顿、策略交接不完整或无法判断时不强行归责个人。链活性保护不是识别定向网络隔离或恶意分叉的万能办法。
- 黑名单只禁止以后新入场，并把当前故障席位标为待安全替换；不能立刻在内核撤销当前有效名单、修改法定人数或判当前授权签名非法。
- 找不到替代者或最终确认人数不足时，必须报告替换受阻，不假称已自动移除。正常轮岗不得不断替换其他健康席位以掩盖这个故障。

### 5.4 黑名单范围与恢复边界

- 不向现任或开发者开放举报拉黑、投票拉黑、任意点名踢人或手动解禁入口。
- 用户于 2026-10-05 确认采用永久禁入：黑名单账号不得再次轮岗，不自动恢复，也不增加人工解禁入口。禁入只针对轮岗资格，不冻结资产、不没收历史已赚收益。
- 同账号改钥、注销再注册或离开排名后重新入围，不删除已确认的黑名单；采用账号级记录，不承诺阻止同一运营者换新账号和新密钥重新获得投票。
- 不冻结普通资产、转账或资源使用，不没收历史奖励，不清票，不改变已冻结或未来升级否决资格。本次不新增实名、押金或资产罚没。

## 6. 共识可用性：不拉黑不等于不会停链

当前等权最终确认人数门槛为 `floor(2k/3)+1`；实际策略权重、pending 策略和网络状况仍需验证。

| 正式人数 k | 所需确认人数 | 必须说明的边界 |
| --- | --- | --- |
| 1 | 1 | 唯一节点停机，链上规则不能自行继续执行 |
| 2 | 2 | 少一人确认，就不能形成新的最终确认 |
| 3 | 3 | 同上；不拉黑也不改变这个事实 |
| 4 | 3 | 剩余三人正常确认时，人数上足够 |
| 21 | 15 | 单人离线、其他 20 人正常时可继续；缺 7 人只剩 14 人时不足 |

因此 1→2、2→3 直接加入未启动成员可能立刻卡住最终确认，不能等三轮处罚来救链；本版甚至明确在不足 21 人时不处罚。启动运维必须说明参与者实际启动/同步安排及恢复路径，不把运维准备变成现任审批权，不降低共识门槛伪造成功。

稳定 21 人阶段一人持续离线且名单不变，会漏掉其每轮约 6 秒的窗口，即约 1/21 的出块机会；其他节点不会立即代打。按块发奖可以不给这个人新增奖励，但不能消除这些空窗，也不能保证故障不会扩散。

## 7. 收益规则：零有效块＝零新增节点奖励

### 7.1 什么块能拿奖励

1. 取消没有实际产出的固定备用节点奖励。原 per-vote 路径必须纳入审计，不能让无产出者通过另一条路径领钱；是否同时取消有产出者的原票奖，待“沿用原方案”的分配口径确认。
2. 有效块必须由当时合法调度的账号产生、验证通过并最终进入已最终确认主链。未确认先暂存，不先发钱再追讨。
3. 漏块、废弃分叉块、重复记录不计数；合法空块最终确认后仍计 1 块，不按交易笔数或金额额外加成。
4. 排队、离线、未上岗或被拉黑但没有有效产出，均没有新增节点出块奖励；不再存在固定备用节点奖励，不因注册、排名、在线心跳、候选扩容或 QC 签名另发奖金。
5. 仍处于实际生效策略中的过渡成员，只要合法调度且块最终确认，仍按同一规则计酬；黑名单不能追溯作废合法区块。

### 7.2 纯按块分配草案（待与最新“沿用原方案”要求核对）

本节原公式尚不代表 2026-10-05 已确认保留或取消有产出者的原票奖。奖励资金已确认沿用原方案；以下按期纯块数分配及固定结算周期需与最终分配选择一起定案，不能先作为生产规则启用。

```text
B_e = 本期实际到账且明确允许用于节点奖励的预算
n_i = 节点 i 在本期产生并最终确认的有效块数量
N_e = 本期所有节点最终确认的有效块总数

N_e > 0：节点 i 本期奖励 = floor(B_e × n_i / N_e)
N_e = 0：不分配，预算结转，不执行除法
```

例如预算 1,000 币、有效块共 10,000：出 100 块分得 10 币，出 0 块分得 0 币。不按 210 或 420 候选人数直接平分，不能让不工作的人仅靠入围领钱。

- 使用固定 slot 周期；区块归属产生时的周期，不能因最终确认较晚换到下一期。周期边界和统计全部进入最终确认后才封账。
- 保存待确认产出、最终确认记账游标、周期汇总及个人余额；同一块只计一次，合法空块正常计数。
- 使用最小代币单位的整数和足够宽的中间乘法；取整余数按固定规则结转，总支付不超过实际预算。
- 封账生成已赚余额，领取只扣余额，不根据领取先后重新计算分母；重复领取不能重复支付。
- 每块记账、跨期结算、历史清理均设工作量上限；快照、重放、分叉和重启不丢账、不多发，不清除未完成统计或未领取债权。

### 7.3 不扩大的经济权限

- “不出块没有收益”只指不新增节点出块奖励，不没收以前已赚的钱；账号离线、退出或进入黑名单，仍保留合法已赚余额。
- 普通持有 REX 等的资产收益是另一回事，本要求不取消其收益，也不要求节点买 REX、给自己投票才能领取块奖。
- 2026-10-05 用户确认奖励资金先沿用项目原有 EOS/Antelope 方案，不改成独立账户预充值；本次不授权另设发行参数，不自动挪用 RAM/PowerUp/REX 手续费或 REX 持有人资产。出块者是否保留原按票分配尚待核对；结算边界、历史债权与预算不足处理需在最终分配方案确定后对齐。
- 取消票奖不自动等于取消增发，不授权擅自转移旧 `eosio.vpay` 余额。已有链迁移必须保护旧债权；新规则从明确启用边界记账。
- 核对是否部署 `eosio.bpay` 独立分配合约，不能只关系统票奖，却留下另一套按排名/人数分配节点收益的旁路。

### 8.2 确定性宿主视图与真实调度

拟新增版本化 `get_rotation_context_v1()`，来自区块执行的父状态及协议规则：chain ID、执行上下文身份、确定性最终确认锚点、active/pending proposer/finalizer 策略、真实版本/摘要、账号/密钥映射及必要调度信息。

- 不读网络探测、异步本地 LIB、RPC head、墙上时间或插件缓存作为共识输入；最终确认视图以执行上下文可确定的 `finality_core` 为基础。
- 当前 slot 推导出的策略晋升要纳入视图，不能混淆父块名单和当前块名单；生效版本不能仅靠合约缓存推测。
- `onblock()` 收到的是前一块 header，产出记账必须按此语义对齐；识别漏掉的 slot 要依据真实历史排班，不把某块生产者当作整个间隔的所有者。
- 每个观察区间需要保留足够策略/历史映射，不能跨策略变化随意拼出“三个本人窗口”；重放、快照和不同节点执行必须一致。
- 账号和 BLS 身份映射不能只相信可读 description；黑名单不得改变当前有效策略的签名合法性。

### 8.3 兼容与权限

成员变更、注册撤销和 `actfinkey` 与交接/观察串行协调；禁止其他旧入口绕过队列提交整组名单。保留账号管理自身密钥权利，但不能用变更清除处罚。

不恢复 `eosio.prods`、`eosio.msig`、`eosio.wrap` 的系统管理权限；不改变开发者升级的 14 天公示及升级否决规则。新增宿主、合约和能力必须显式版本化，先在隔离新链测试；旧链迁移、profile 调整及正式部署另行获准。
