## 1. 固定执行顺序

**开发押金模式 → 远程构建和功能验证 → 归档旧链 → 部署新链 → 单 BP TPS 测试并保存记录 → 启动独立历史节点并恢复历史查询 → 其他 BP 逐个加入 → 验收与持续观察。**

单 BP TPS 测试完成前，不启动其他 BP、历史节点或索引后台。BP 逐步加入前，先使新链压测交易能够从历史 API 查询并在浏览器显示。

不得将多 BP 共享主机的结果写成多台独立机器的性能或去中心化资格证明。

## 2. 已确定的押金规则

| 项目 | 固定规则 |
|---|---|
| 普通 BP 准入 | BP 本人授权缴纳 `10000.0000 AIC` 后才能注册并参与出块候选 |
| 押金用途 | 履约担保；与 CPU/NET 质押、投票资产、奖励资金分开 |
| 押金托管账户 | 独立协议账户 `eosio.bond`，在治理封存前建立 |
| 罚没账户 | 独立协议账户 `eosio.bslash`，在治理封存前建立 |
| 退款 | 完成原生出块和最终确认职责交接、处理旧待结算窗口后冷却七天；退出检查点最终确认后领取 |
| 冷却时间 | `604800` 秒；不为测试或演示缩短生产规则 |
| 罚没触发 | 正式进入现有永久黑名单，罚没该 BP 专用押金 |
| 罚没资金去向 | 锁入罚没专用池；本版不提供转出、分配或销毁接口 |
| 普通撤票、轮岗、维护 | 本身不构成罚没理由；原生职责交接前仍需在线履职 |
| 既有违规证据 | 不因注销、退出、重新缴纳、重新注册或换密钥而清除 |

`eosio.token` 仅继续承担当前 AIC 代币合约职责，不作为押金或罚没资金的托管账户。

采用新链初始化方式，不以放宽“治理封存后禁止新建 eosio.* 账户”的保护来兼容旧链。两个托管账户必须在封存前由系统初始化建立，不预先手工占用账户名。

托管权限和资金流必须按以下方式验证：

- 初始化时，两个账户的 owner/active 均无普通私钥，阈值为 1，仅由 `eosio@eosio.code` 授权执行系统资金流程。
- 治理封存后，受保护账户 owner 权限的阈值为 1，但 keys/accounts/waits 均为空，不能满足授权；active 无普通密钥，仅保留协议允许的 `eosio@eosio.code` 和该账户自身的代码权限。封存后不开放普通权限修改路径。
- BP 永久拉黑时，先原子扣除其可退押金并记为待结算罚没；实际罚没决定块最终确认后，任何人均可触发一次结算，资金只能进入 `eosio.bslash`。待结算期间也不得退款。
- `eosio.bslash` 不部署可提款代码，本版系统合约不提供该池的转出、分配或销毁动作。开发者没有直接提款私钥。
- 保护账户的合约升级仍遵循既有开发者升级提案、七天审查及 BP 否决机制，并非必须获得 BP 肯定投票。开发者不能绕过该流程直接更新系统合约。“本版锁池”不代表今后经治理升级的代码永远不可改变；`eosio.prods`、`eosio.wrap`、`eosio.msig`、`eosio.null` 的永久限制继续保留。

本次不新增“拒绝最终确认签名”的黑名单条件，也不实施此前讨论的扩大确认委员会或超时接管方案。

4. 建立新的 genesis、数据目录、运行目录和链 ID；本次不新增服务器。普通 BP 与测试账户使用 12 字符原生名称，协议固定系统账户保留所需名称。
