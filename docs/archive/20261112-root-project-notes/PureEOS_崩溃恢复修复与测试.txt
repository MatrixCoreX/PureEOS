一、问题与修复
原问题：SIGKILL 后，区块日志只保留最终确认区块，而 finalizer 的安全记录
已锁定更高的可逆区块。单节点重放后找不到原分支，无法安全地继续签名。

本次修改链底层，不修改系统合约及共识门槛：
1. reversible_recovery.hpp / .cpp：增加 blocks/reversible/recovery 下的本地
   恢复记录。每个原始签名区块绑定链 ID，并附完整性校验；临时文件写完并
   同步后原子替换。并发写入去重，只清理已经持久化到不可逆日志的高度。
2. controller.cpp：本地产块和接收区块在推进本地签名安全状态前保存恢复
   数据。启动时保留旧分支库并补齐恢复记录，再按正常头部、签名、QC 校验
   恢复分支，之后通过原有区块执行路径校验交易。缺失必要祖先时拒绝启动。
   恢复阶段不重新发送投票，也不通过旧 QC 改写已有安全记录。
3. fork_database.hpp / .cpp：为升级回填提供全部分支的原始区块；启用恢复
   记录时不在读取后立即删除旧 fork_db.dat，避免回填途中崩溃丢失来源。
4. finalizer.cpp / .hpp：safety.dat 不再原地截断覆盖，改为临时文件写入、
   同步、原子替换。保留原 v1 格式及非当前配置密钥的历史安全状态。
   保存失败时仍不发布投票；没有清空、回退安全记录或放宽防重复签名规则。
5. block_log.hpp / .cpp：增加日志同步接口，清理恢复记录前先同步不可逆
   日志；分段日志在封存当前段之前也同步文件。正常情况下每推进 256 个
   最终确认高度清理一次；未最终确认分支不按“只保留最近几块”强行删除。
6. producer_plugin.cpp：修复协议特性 API 递归遍历中的 flat_map 迭代器失效。
   原实现递归插入依赖后继续使用旧迭代器，导致漏报 PUREEOS_ROTATION_CONTEXT。
   现在重新按摘要查找后更新状态；真实 API 回归检查完整性、唯一性和依赖顺序。

三、边界与运维注意事项
- SIGKILL 后直接启动仍应拒绝脏数据库；使用 --replay-blockchain 重建状态，
  必须保留同一链的 blocks（含 reversible/recovery）和 finalizers/safety.dat。
  备份应来自一致的时间点，不能随意混用不同时间点的分支和安全记录。
- 不可把此修复理解为删除安全记录后重新签名；已丢失且没有备份或对等节点
  提供的旧锁定区块，不能凭空恢复。本次保留了此前三条失败测试链的证据。
- 默认启用于原生创世及 profile 2 治理链，已有恢复目录也会继续启用。
  profile 1 仅有新快照、没有创世日志和恢复目录的入口不在本轮保证范围。
- 本次主要验收完整不可逆日志模式；关闭区块日志时恢复记录不自动清理，
  不能据此承诺无日志模式可从脏状态自行重放。裁剪、分段、人工截断和磁盘
  断电损坏等组合需另行验收；fsync 不等于已通过真实断电/硬件故障测试。
- 本地短测不代表跨地域延迟、长期磁盘增长、吞吐压力或全部故障组合已通过。
- manual-test-chain 的现有进程、数据和内置运行时没有被替换。
