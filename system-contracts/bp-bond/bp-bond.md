# 新链 BP 押金模式

[English](bp-bond.en.md)

本扩展基于已验证的系统合约 `15dea1aa8a4b158eb771c5b13947ddeaafd28910`，用于新链部署。保留单选整数投票、原生出块/确认轮岗、10%/90% 资源分配、精确 1% 奖励与减半、七天升级审查，以及现有永久黑名单及全链中断保护。

## 固定规则

- 每个普通 BP 本人授权缴纳 `10000.0000 AIC`，才能通过 `regproducer` 或 `regproducer2` 注册并进入出块候选。不支持部分缴纳、额外加押或用 CPU/NET 质押替代押金。
- `eosio.system::init` 自动初始化押金模式，在治理封存前建立独立 `eosio.bond` 和 `eosio.bslash` 账户及其 RAM；AIC 代币合约账户 `eosio.token` 不承担托管。设置失败时初始化整体回滚。
- 固定押金不增加票数或轮岗优先级。候选仍须满足有效票数、出块/BLS 密钥、维护状态与永久黑名单要求。
- 正常退出先注销注册，原生排班、确认身份、轮岗 active/target 中的旧职责仍需完成。没有合格替补时保留旧职责及押金，不为退出单独降低确认门槛。
- 合约确认没有旧职责和待结算窗口后开始七天 (`604800` 秒) 冷却；退款还要求退出检查点最终确认，且没有永久黑名单。由 BP 主动领取，不使用 deferred transactions。
- 正式进入现有永久黑名单时，立即罚没全部专用押金并取消退款资格。判罚记录本身最终确认后，任何人可提交 `settlebond`，将固定罚没金额转入 `eosio.bslash`。在结算前资金仍作为不可退款的待罚没负债锁在 `eosio.bond`，不依赖结算者决定是否罚没。
- 本版没有从罚没池转出、分配或销毁资金的接口。普通账户无法使用托管账户私钥提款；账户权限和代码继续受既有原生治理规则约束。
- 撤票、正常轮岗和安全交接后的维护本身不构成罚没；退出、重新缴纳、注册或换密钥不清除既有违规或永久黑名单。退出后仍保留实际合法出块的历史奖励领取权，押金本身不产生奖励。

## 接口与状态

| Action | 行为 |
|---|---|
| `initbpbond()` | 由新链系统初始化自动调用；必须在治理封存前，由系统授权，一次性建立固定政策和独立账户 |
| `bondbp(producer)` | BP 本人授权，原子转入恰好 10,000 AIC；失败时所有资金与账本变更回滚 |
| `exitbond(producer)` | BP 本人申请退出，停止新候选资格，等待旧职责安全交接 |
| `refundbond(producer)` | BP 本人在七天冷却及最终确认等条件满足后领取 |
| `settlebond(producer)` | 无需特权的固定罚没结算；调用者不能选择金额或目的地，同一押金只能结算一次 |

`bpbondcfg` 记录强制模式、固定冷却期、锁定押金、待结算罚没、已入池罚没和累计退款。`bpbonds` 每个历史 BP 一条本人支付 RAM 的记录，状态为 bonded/exiting/cooling/refunded/slashed（0/1/2/3/4）。不逐块追加历史表。

无额外转账时，托管余额应为 `eosio.bond = locked + slash_pending`、`eosio.bslash = slash_settled`。直接向托管账户转账不创建个人押金记录，不能据此注册 BP；额外转账属于未计入押金的余额。

罚没记账与黑名单标志在同一执行中提交，不在缺勤结算路径调用外部接收者；结算失败不恢复退款资格。退款和罚没转入池均使用原子交易。若发生正常链回滚，对应状态与资金一并回滚。

## 部署与验证范围

只能按新链初始化部署，不提供旧链免押金阶段、临时关闭门槛或封存后创建系统账户的旁路。协议创世签名者仅承担引导；首个真实 BP 同样缴纳押金后才注册并接替它。

远程构建与真实 WASM/原生控制器功能验证通过后，归档旧链，在保留的测试服务器初始化新链。先以一个 BP 运行一轮纯 AIC 转账 TPS 测量并保存记录；之后启动独立非出块 SHIP 历史节点恢复 PureHistory，再逐步加入其余健康 BP。每轮以实际源码、WASM/ABI、二进制、配置和证据哈希为准。

本版不新增 BLS 拒签判罚，不实施更大的确认委员会或超时接管。失去最终确认时不降低门槛，也不根据心跳或本地日志伪造个人违例；押金不能保证超出既有容错范围后的自动恢复。

## 治理封存后的账户权限

原生封存流程将两个托管账户纳入保护清单。owner 门槛为1，但 keys/accounts/waits 均为空；active 门槛为1，没有普通公钥或等待项，eosio@eosio.code 与账户自身@eosio.code 各权重1。罚没账户初始没有支出代码。开发者升级私钥不是直接提款权限；未来修改代码仍需七天审查和 BP 否决流程。
