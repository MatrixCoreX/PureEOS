# 全网公钥账户按需增长

本版本移除钱包、余额记录和资产登记的全局数量门槛，以及每币种累计RAM预算1TiB的人为门槛。既有config.policy中的max_wallets、max_balances、max_assets、max_native_payers保留为兼容字段，均不再限制准入。旧值1000/4000不会阻止新的付款记录。

每次新增公钥/余额/命名收款行仍须由本笔交易额外支付AIC手续费，真实购买RAM、核验实际取得的配额，再全额记入或转出本金。已存在的记录不重复购RAM。费用高于签署上限或任何后续步骤失败，整笔回滚。保持白名单、代码哈希、持有人证明、撤销代次、费用公式、中继收入、免费claim、注册桥接及原生资源规则。

这里的按需增长不代表物理无限容量：链上RAM供给/市场、节点存储和交易资源、原生限制与整数表示仍然有效。不改变共识、节点CPU/NET上限或原生RAM市场，也不承诺吞吐容量。

## 原地兼容

既有config、wallets、balances、assets、费用表、签名域、动作参数与回执布局保持不变。新增growth singleton，布局为version:uint32=1，wallet_count:uint64，balance_count:uint64，asset_count:uint64。

第一次新增记录时，从原config累计计数初始化growth，并对旧ID与计数关系作一致性检查；与该次购买、记账在同笔交易中提交或回滚。没有扫描全账本、重新创建账户或可由管理员改余额的迁移动作。升级后尚无新增记录时，growth为空是正常状态，读取方可使用旧config计数。

有growth后以其64位计数为准。config中的旧32位计数继续作为兼容视图更新；到uint32上界后饱和，不回绕、不拒绝新增。余额计数包括内部余额记录和KEY出资开立的外部代币行的累计次数，不等于当前内部表行数。64位计数、ID和累计RAM相加均保留溢出检查；这些检查不会把有限范围的整数伪装为无限。

本次只升级KEY。Signup代码不变，KEY继续绑定已审查的Signup3c03；Signup的桥接依赖实际AIC付款，不绑定KEY代码，因此不需要升级Signup。客户端必须在激活前适配明确的新/旧KEY代码哈希，未知代码仍拒绝。

## 验证与发布条件

所有编译和测试远端执行。包含实际旧30f6 WASM初始化并存入余额、验证旧小上限拒绝、原地替换新代码后数据完全保持、超过旧限制的真实付款，以及三币种三路线/费用/回滚/注册/claim回归。近uint32、uint64和1TiB的测试使用独立TEST ONLY状态种子；它们验证算术、实际新增购买和失败回滚，不表示真的建立了数十亿账户或购买了TiB物理RAM。种子程序不得用于公开部署。

代码/ABI/审查文档的精确哈希先发布，再通过eosio.dev原生提案、公示和有效BP否决流程。TEST完整1800秒，生产规则不变。只有不可逆执行及随后实际验证成功才算升级完成；编译和候选源码发布不表示已生效。
