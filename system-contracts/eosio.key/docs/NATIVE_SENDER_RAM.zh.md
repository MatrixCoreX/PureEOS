# 命名账号自付资源的公钥充值升级审查

本升级已于2026-11-11通过提案5在区块686081不可逆执行。完整部署证据及三路线实际费用见 [中文报告](../../../deployments/20261111-key-native-ram-r1/activation/REPORT.zh-CN.md)。

本升级仅修正命名账号转公钥：发送账号一次签署同一交易里的 deposit 声明与本金 transfer 两个顶层动作，以自己的 CPU/NET 提交。deposit 在发送方明确授权的顶层帧中，为新增钱包、索引和余额记录指定发送方 RAM 付款人；既有记录保留原付款人。没有手续费资金转账、执行费、最低费、中继费或自动购 RAM。发送方 RAM 不足或本金到账不匹配，整笔交易回滚。

配置、动作和全部表的 ABI 字节保持不变；deposit 的 max_fee 必须为零，旧的三动作付费报文拒绝。内部 pending 锁在分配记录和预记余额前建立，只有严格匹配的第二根动作实际到账后才解除并发出零费用回执，到账前不能使用预记余额。费用回执的 RAM 字段只代表费用出资购入部分，不能解释成发送方实际 RAM 为零。

只接受已审核、已完成共享托管 RAM 接入的代币。当前 AIC/USD/CNY 已准备；普通发送方不会为新发行商静默接入或购买合约 RAM。公钥转公钥与公钥转命名仍按原规则收费及按需购买真实 RAM，签名证明、费用上限、准备金、领取、注册和全部原生治理规则保持。

已在用户明确允许的本机隔离链，以实际生产原生运行时和固定 CDT 构建验证191项，并通过30项SDK测试，包括真实 RAM 付款人、重复转账零新增 RAM、发送人无AIC的USD充值、真实不足RAM晚期回滚、旧7db记录升级保持、公钥路线与重放/证明/中继钥匙回归。保留失败尝试和仅测试夹具修正，不宣称多节点共识/TPS或手机真实付款验收。

REVIEW.json 绑定源文件、WASM、原始ABI、资格证据及完整1800链秒公示要求。Git发布回执另外绑定具体提交。使用现有代码RAM，不扣用户账本余额；不修改原生、系统、代币、账号权限或BP服务。用户要求先升级测试网，随后钱包直接兼容新格式；钱包原有链身份/代码信任校验继续保留，但不新增专门的升级生效拦截。
