## 最终行为

中继本人可通过 `setrate` 设置动态基础手续费的 10%–30%。四位小数 AIC 的整数计算为：

`service_atoms = max(1, ceil(base_atoms × fee_bps / 10000))`

`total_atoms = base_atoms + service_atoms`

这不是按转账本金抽成。基础费仍按 PowerUp CPU/NET 市场占用曲线、操作工作量、适用的新行费用和最低基础费计算；RAM 项不是实时逐字节账单。领取中继收益仍免应用手续费、全额到账，由领取人承担原生资源及必要的 token::open RAM。

没有新增中继 HTTP 进程、路由、热钥或子权限。四项未启用登记不能执行中继转账，未补充 HTTPS 入口不能直接开启。登记和费率行由对应 BP 支付 RAM，原账户权限保持一致。

新版 SDK 把具体费率加入持有人签名，改价后拒绝旧报价；原生 cleos 保持原二进制和源码，旧请求保留原 30% 费率上限及签名总费用上限，并可按更低费率执行。请求使用末尾可选扩展，旧表和钱包身份不迁移。

按用户后续要求，四段公式和原有计费说明合并在页脚“费率计算公式”中，默认收起；预估金额、CPU/NET/RAM、费率选择始终可见。保留中英文、明暗主题和手机布局。

## 实际资源与暂停恢复

设备仍为共享 Intel Cascadelake、4 vCPU/2 guest cores、8125768 KiB 内存的原测试 VM。资源耗尽时仅约 31 MiB 可用、交换空间近满，出现 SSH 和测试 worker 超时。得到用户明确允许暂停整个链及历史后，于 02:50:34Z 正常停止原 26 个节点及后台，保留数据；可用内存恢复约 7.2 GiB，完成构建后恢复。

创世 BP 当时处于候补，其他 BP 默认不从过期链头生产。24 个合格 BP 和历史节点的链头一致；已拉黑的 germanycrest 是落后节点。选择一名实际在岗 BP，在其正常轮值窗口临时允许过期链头启动，保持原密钥、安全锁及 21/15 法定票数；真实出块与不可逆确认恢复后，配置已逐字节还原并重启。四个原历史容器保留相同 ID/卷；等待 Elasticsearch GREEN 后恢复 API/indexer/投影，核对历史及普通业务。

在暂停前已发现 germanycrest 因三个真实最终化零生产窗口被原生永久拉黑，`ban_final_block=125869`、`ban_record_block=125872`；其进程在运行但链头已停于 112934。没有清除封禁、退款、代造签名或执行押金结算。最终实际为 25 注册、24 合格，25 个 BP 进程加 1 个历史进程，实际原生 21/15；不是 25 个健康合格 BP，也不代表容量或延迟问题已经解决。
