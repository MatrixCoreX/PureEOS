# eosio.key：付费 RAM 登记与发送方承担新收款记录费

已实现并在独立 Vultr 安全测试机完成回归。所有币种，包括 AIC 本金及 AIC 费用预存，须先在同一原子交易中真实购买 RAM 并执行 `regtoken`；额度来自原生实际购买字节。任意原生账户可追加预算。新公钥、币种余额和必要费用记录按保守字节预算计入对应币种，未登记或预算不足的新分配回滚；已有记录可复用，收款公钥无需预开户。

新增收款公钥及余额行的费用由本次付款方额外承担：文本发送账户使用自己的预存 AIC，公钥发送方使用自己的 AIC，收款本金全额到账。已有记录不重复收取创建费用。登记人的预购字节与每笔发送方费用分开记账，正常费用不会自动购买额外 RAM。

| 测试进程 | 两轮结束后私有 nodeos / keosd 为 0 |

低占用测试费率的实测单笔总费用：文本转新公钥 0.1050 AIC、复用记录 0.0100 AIC；公钥经 BP 中继转新公钥 0.1365 AIC、复用记录 0.0130 AIC。以上是当前功能测试参数，不是正式价格承诺；动态 PowerUp 市场占用倍率、执行量、新行数和用户费用上限仍适用。

**资源隔离仍未通过，公开发布资格仍为 false。** 已付费登记的恶意发行合约仍能在提币时额外向 eosio.key 计费 4,330 字节，钱包行计数不变。71 项观察包含这一风险的成功复现，不能将 PASS 解释为该漏洞已修复。登记证明出资，不代表发行代码审核或独立托管隔离。

构建和所有执行仅在既有独立 Vultr 安全机进行，使用已留存 TEST CPU4 / NET1MiB 运行时、正常系统 WASM 和独立临时私有链；本机仅源码编辑、编排、接收与哈希校验。未部署公开链、修改 nodeos / 系统合约、启动普通账户中继或运行 TPS 测试。开发表结构增加 RAM 字段，已有部署需要单独迁移评审；用户签名协议保持 2。

失败尝试保留：构建 r1 因编排脚本换行转义出错，r2 修复后构建通过；功能 r1 的新增预算用例改变了旧 SDK 余额断言所依赖的状态，调整测试顺序后正常 r2 全部完成。没有将失败记录改成成功。
