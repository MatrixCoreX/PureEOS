## 1. 命名账号 → 公钥

例如A给公钥B转100 AIC，或100 USD：

1. 钱包让A签署**同一笔交易的两个顶层动作**：`eosio.key::deposit(A@active,max_fee=0)`，随后代币合约`transfer(A@active)`把准确本金转入eosio.key，附言为`atomic key principal`。钱包不先转手续费，也不预存fee余额。
2. 第一动作明确取得A授权，在该顶层帧为缺失的钱包、索引、币种余额记录指定**A为RAM付款人**。避免依赖合约自授权内联动作去扣A的RAM。
3. 发送交易使用A自己的CPU/NET。新记录实际占用A已有RAM额度；已有记录保留原付款人，不重复创建、不重复收记录费用。
4. 合约先设内部交易锁，匹配并收到第二动作的准确本金后才完成结算。本金全额记给B；未到账前预记余额不可支出。任一步失败，整笔本金、账本和RAM分配一起回滚。

**费用：执行费0、最低费0、中继费0、合约收取的RAM购入费0。** 不自动买RAM；A可用RAM不足时交易失败，A自行管理自己的资源。这里“RAM费0”表示不额外扣AIC，新增记录仍真实占用A的RAM。这个合约不会因B之后转出就自动把记录付款人改成B或释放A的额度。

USD/CNY在本方向不需要额外AIC手续费余额。接入的代币仍必须经过既有审核及共享托管RAM准备；发送者不会替陌生发行商静默开通接入。旧版三动作付费充值报文现在会拒绝，钱包test29直接使用新格式。

本轮公网上的AIC、USD、CNY和重复AIC共4笔均已不可逆：全部本金到账，实际费用回执各项为0，钱包与余额行付款人为gptgenesisbp。原生隔离测试另外验证了无AIC的USD发送人、真实RAM不足回滚，以及已有记录几乎无剩余RAM时仍可转账。

## 2. 公钥 → 公钥

1. 发送方私钥在钱包本地签署收款公钥、币种、本金、最大费用、选定中继及费率，绑定完整交易和有效期。
2. 中继以自己的命名账号签名并提供原生CPU/NET；合约独立验证持有人证明、交易绑定、中继资格和费用上限。
3. 发送方公钥账本支付完整本金，另从其AIC余额支付费用；收款方取得完整本金。转USD/CNY也需要发送方有AIC支付这一路的费用。
4. 收款钱包或币种余额缺失时，按保守字节预算计RAM项，并从本次费用实际购买eosio.key所需RAM；购买/记账失败则原子回滚。已有记录时RAM创建项为0，执行和中继费用仍存在。
5. 实际RAM购入支出用于系统RAM市场；**其余本笔执行收入及中继手续费计入选定中继的可领取收入**。执行计价基于链上PowerUp市场占用，并非对该中继实际CPU/NET现金成本逐笔报销。

本轮新公钥接收0.0001 AIC的实测总费0.0335 AIC：RAM购入0.0037、执行收入0.0220、中继手续费0.0078。1536字节预算实际买到1585字节。该笔中继可领取收入增加0.0298 AIC；这是本次动态市场下的实例，不是固定报价。

## 3. 公钥 → 命名账号

1. 钱包签署持有人证明和提现交易，中继提供原生CPU/NET，合约校验同样的资格、费率、费用上限和交易绑定。
2. 本金从公钥账本转为代币合约对命名账号的真实余额；发送方另付AIC费用。
3. 收款命名账号已有该币种余额行时，不重复购入该行RAM；缺失时仍由原有公钥出款路线按需收RAM项、实际买RAM并建立记录。本次升级没有改动这个机制。
4. RAM购入以外的执行收入和中继手续费归中继可领取收入；公钥发送USD/CNY仍需要AIC手续费余额。
